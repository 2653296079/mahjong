# 风险与性能评估

本目录提供可复现基线。模型没有按本轮结果重新拟合；原始概率仍作为“采样风险估计”显示，界面说明了偏差和适用范围。

## 复现

在项目根目录运行：

```bash
node evaluation/run-risk.js --hands 24 --worlds 150 --seed 20261016 --out reports/risk-baseline.json
node evaluation/performance.js --out reports/performance-node.json
node --test tests/evaluation.test.js
```

报告记录种子、风格、规则／分析器版本；风险报告还记录内联引擎 SHA-256（换行统一为 LF），便于确认评估对应的代码。性能值随机器与负载变化。

## 风险测量的含义

模拟 v1、v2、v3 三种对手，各 8 局，共 24 局。每四个可测的摸牌决策抽取一次，对该决策全部合法弃牌种类评估，不用真实暗牌筛选候选。预测器只能取得自己的手牌、公开牌及牌墙张数；访问其他玩家暗牌会直接抛错。预测完成后，评估器读取模拟真值，判断某候选能否被至少一位未受过胡限制的对手合法胡牌。

因此观测标签是“该候选此时可被胡”，并非真实出牌后观察到的放炮，更不是整局输赢。听牌标签则按真实手牌逐一加入所有可能和牌种类枚举。分析前后还检查真实状态未被修改。

2026-10-16 记录的结果：

| 指标 | 结果 |
| --- | --- |
| 决策点／候选弃牌 | 197／2071 |
| 可被胡的候选 | 35，比例 1.6900% |
| 平均预测风险 | 5.3333% |
| Brier 均方误差（越低越好） | 0.019574 |
| 始终预测 0 的 Brier 参照 | 0.016900 |
| 固定分箱加权绝对偏差 | 0.037141，即约 3.71 个百分点 |
| 对手听牌观测 | 591 次中 82 次；观测 13.8748%，平均预测 28.0541% |

`Brier = 平均((预测概率 − 0/1标签)²)`。分箱边界预先固定为 0、2%、5%、10%、20%、100%，各箱按样本数加权。报告保留每箱样本数、命中数与三种风格的分项；空箱值为 null。

本批样本里模型偏高，整体 Brier 还不如始终预测 0 的参照。始终预测 0 只是一项误差参照，不能由此推导它是好的弃牌策略。

同局的多个候选和决策相互关联，2071 条不等于 2071 个独立样本。模拟风格共享同一引擎，不能代表真实玩家；仅 35 个命中不足以精确校准尾部风险。增加采样数量只能减小抽样波动，不能纠正对手分布假设的系统偏差。

下一轮先积累更多独立牌局和实际玩家反馈；拟合或修改先验时按整局分割训练、验证与新保留测试集，保持风格覆盖，预先固定评价口径，再比较 Brier、分箱、误报漏报及策略结果。当前报告已经被查看，不能在据此调参后继续充当最终未见测试集。

## 性能基线

Node v22.16.0 的开发电脑，顺序遍历 36 个基础题两次。基础项包括取候选；讲解项对 30 道弃牌题的前三个候选生成完整宽听路线。首次遍历共享有界缓存，并非每题都重新冷启动。

| 遍历 | 基础 P95 | 讲解 P95 |
| --- | --- | --- |
| 首次 | 27.81 ms | 39.44 ms |
| 第二次 | 0.38 ms | 1.08 ms |

硬件、每题耗时与完整统计见 [性能报告](../reports/performance-node.json)。测量不包含风险采样、DOM、绘制，也不是浏览器或真实手机数据。真实手机 P95、长任务和交互延迟仍待实测，不能宣称达到计划中的手机性能目标。
