# 转转麻将 · 练牌室

一个可以离线玩的转转麻将练习器。你对战三位电脑玩家，边打边看牌效、公开信息推算的放铳风险，并在每次出牌后看到简短复盘。也可以开一间房，和朋友一起打（人数不够由电脑补位）。支持游客练牌，也可在游戏服务器创建账号，保存自己的完整对局与个人数据。

**在线玩：** https://2653296079.github.io/mahjong/

## 开始

打开后先选「牌效训练」「单机练习」或「联机打牌」。牌效训练先作答，再看向听、有效牌、宽听路线和概率；单机中可返回主界面继续本局。联机返回首页会离开房间。

- 电脑：打开在线地址，或直接用浏览器打开 `index.html`。
- 手机：用 Safari 或 Chrome 打开在线地址，可以添加到主屏幕。竖屏和横屏均可玩。
- 主机入口：Windows 双击 `打开联机麻将.bat`，自动启动或复用服务并打开大厅。

### 三维牌桌（v30）

[在线体验 3D 麻将机](https://2653296079.github.io/mahjong/?build=v30&view=3d&play=1)。首页有「3D 试打一局」，牌局中的「更多」可切换三维牌桌。本机也可双击 `试玩3D麻将.bat` 启动独立预览服务。

使用 Blender 制作的 27 种牌、牌桌、牌背和配件，支持抬牌、摸牌／出牌动画、坐席／俯视切换和拖动空白桌面调整视角。点一下选牌，再点同一张打出；悬停或首次选牌查看原有逐张分析。随时切回二维，可继续当前牌局。详见 [三维试玩说明](三维试玩说明.md)。

麻将机开局包含收牌入机、洗牌、四方升墙、中央掷骰和三轮每家各抓四张。骰点说明与金色接牌口标记对应；结算中点「收牌洗牌 · 下一局」播放下一轮。可随时跳过动画。

轮到你时点击手牌打出。触屏设备需要点两次同一张牌，避免误触；只高亮实际点中的那一张，改点另一张同种牌会转移选择。可碰、杠、胡时操作栏会出现按钮。键盘快捷键：`H` 胡、`P` 碰、`G` 杠、`空格` 或 `Esc` 过。默认不限时；限时模式可在设置中开启。打开弹窗、手机牌况抽屉或切到后台时，倒计时会暂停。

带讲解练牌时，将鼠标移到任意一张可打的手牌上，就会在牌旁显示这张弃牌的向听、有效牌种与未见张数、下一摸概率，以及与推荐弃牌的差距。一向听会补充摸牌后如何调整到较宽听口的路线。键盘 Tab 聚焦、手机第一次点选也可查看；第二次确认才出牌。测验、先判断后反馈或关闭提示时，出牌前不会显示分析。`Esc` 或面板右上角可收起。

打出的牌按实际先后顺序累积在中央牌河。「显示来源」可切换四家不同颜色的外壳，牌面图案不变；也可在设置中立即切换。被碰杠取走的牌移到所属玩家的副露区，中央显示取走张数。手机空间不足时可在各家牌区、中央牌河内滚动查看。

每把结束，结算中会显示四家剩余手牌，先列其他三家，再列自己；碰、杠与收炮的和牌张分开显示。荒庄也能看。关闭后可点「查看本局手牌与结算」重新打开。单机与联机均支持；联机默认在结束约 30 秒后续局，其他玩家也可以提前继续。有人已开始下一局时，旧结算的按钮会变成「返回当前牌局」。

## 和朋友一起打（联机）

1. 打开统一游戏网站，点「联机」，自动连接大厅。
2. 未登录以自动编号的访客身份加入；登录后直接显示注册账号名。
3. 房间号留空创建新桌，或者填写好友的房间号。点「开始对局」即可打牌，空位由电脑补齐。
4. 点击「复制邀请链接」发给朋友。

大厅实时显示在线总人数、已登录账号数和访客数。同账号／访客的多连接各算一人，机器人和诊断探针不算人数。人数推送不会清空正在填写的房间号。

后台联机服务没有启动时自动拉起，已经启动则复用；整个网站入口没有运行时，主机上双击 `打开联机麻将.bat`，自动启动或复用入口并打开大厅。玩家无需处理 IP、端口或局域网设置。原手机入口及 frp 启动脚本也转到统一启动器。

网页和账号入口持续在线，联机进程按需启动。服务崩溃后可自动重新启动，但原局会保留为中断存档，不能无损续打；普通网络断线仍由电脑托管并可重连接回同一局。部署、启动器、统一公网网址配置和截图见 [联机大厅与自动启动](联机大厅与自动启动.md)。

服务器负责发牌、判定和记分，局中只下发自己的暗牌；终局公开四家剩余牌。出牌立即显示等待确认，服务端先回传已确认操作再推进电脑，讲解和风险随后计算。连接状态中仍可查看网络往返和操作确认耗时。

## 账号与个人对局档案

从运行新版 `node server.js` 的游戏地址打开，在首页「登录 / 我的账号」注册。用户名唯一，英文不区分大小写、全角字符会统一处理。登录后新开的单机与联机对局可保存至服务器 SQLite 数据库，按人机和真人同桌分别统计战绩、收支趋势、手动弃牌的基础牌效，并可查看、下载历史完整牌谱。

单机断网时保存待传队列，登录原账号后自动重试。联机由服务器存档，局中不能通过账号接口查看完整暗牌；未完成或中断的对局不计胜率。当前没有忘记密码找回，可凭原密码修改密码。GitHub Pages 和离线文件继续支持游客，账号请从 Node 服务器地址使用。

需要 Node 22.16+；默认数据库在 `data/mahjong.sqlite`，也可用 `MAHJONG_DB_PATH` 指定持久化位置。数据不会随代码提交。归属、统计口径、备份及截图见 [账号与对局存档](账号与对局存档.md)。

## 规则

| 项目 | 本游戏采用的规则 |
| --- | --- |
| 牌 | 万、条、筒各 1–9，每种四张，共 108 张；没有字牌 |
| 开牌 | 本桌一掷两骰；庄家起逆时针数人，从选中家右侧往左跳过总点数墩，在下一墩接牌。三轮各抓四张、各补一张，庄家再摸一张；四方 14/13/14/13 墩 |
| 行牌 | 不能吃，可以碰、暗杠、大明杠、补杠 |
| 胡牌 | 四组面子加一对乱将，或小七对；四张同牌可作两对；小七对和平胡同价 |
| 鸟 | 每局预留六张鸟牌；1、5、9 算中鸟。0 只为 30 元，1–5 只为只数 × 5 元，6 只为 60 元 |
| 收炮 | 放炮者付 `5 元 + 鸟钱` |
| 自摸 | 其他三家各付 `10 元 + 鸟钱` |
| 杠钱 | 暗杠三家各付 10 元；大明杠放杠者付 15 元；补杠三家各付 5 元 |
| 其他 | 可一炮多响；补杠不可抢杠；放过一次炮后，在自己摸牌前不能再胡炮；荒庄无赔付 |
| 转转 | 真人赢牌不下桌（一直坐在桌上）；电脑赢牌下桌，等待区的人补位，等待区有真人时真人优先上桌；可在设置中关闭 |

这些是本练习器的牌桌规则，不代表所有地区的麻将规则。

## 练习功能

- **专项与复习：** 先降向听、听得更宽、小七对、数未见牌、副露做牌、碰牌取舍六个主题。36 个基础局面（30 道弃牌、6 道碰／过选择）和 72 道保留变式，共 108 条题目，题库版本 `lessons-v3`。变式首次成绩单独统计；换花色或映射牌号的变式不算新的知识点。错题记录错因，答对后按 1、3、7 天安排复习；记录可导出和恢复。
- **三个实战模式：** 在设置中选择带讲解练牌、先判断后反馈、整局测验。测验期间隐藏答案，结算后查看最多三条基于当时信息生成的关键弃牌回顾。
- **出牌讲解：** 对每个候选弃牌先比较向听，再比较有效进张；列出每种可进的牌及未见张数。一向听时会演示下一摸后怎样弃牌，形成更宽的听口。
- **概率依据：** 在“未见牌随机分布”的简化假设下，下一次自己摸到有效牌的基准概率为 `未见有效张数 ÷ 未见总牌数`。未见牌包含对手暗牌和预留鸟牌，不能当成牌墙中确定存在的牌；对手行动和后续改牌会改变概率。
- **局势分析：** 对对手手牌做随机采样，估计听牌和放铳风险。联机时在后台计算，完成前可先查看基础牌效，失败时可重试。初步模拟评估发现概率偏高，界面提供口径说明；增加采样数不能消除模型假设的偏差。详见 [风险与性能评估](evaluation/README.md)。
- **每手复盘：** 出牌后显示与牌效推荐的差异，以及该张牌的采样风险。
- **防守道场：** 在中后盘局面里练习选弃牌，并比较候选牌的进张与风险。
- **统计和牌谱：** 训练统计保存在当前浏览器的本地存储；本次游戏的牌谱可导出、逐步回放。清除浏览器数据会清除本地统计。
- **离线使用：** 通过 HTTPS 访问后，Service Worker 会缓存页面供离线打开。

## 开发与验证

项目无构建依赖。二维页面、样式、核心引擎和交互代码都在 `index.html`；`server.js` 提供本地静态服务器和联机服务，`sw.js` 提供离线缓存。可选三维视图按需载入 `assets/table3d/`、本地 Three.js 0.180.0 和 GLB 模型，无需 CDN 或 npm 安装；通过 HTTP(S) 使用，直接打开文件时可继续使用二维。

联机的服务端代码在 `server/`，它**不维护第二份引擎**：`server/rooms.js` 启动时直接从 `index.html` 里取出内联的引擎来跑，所以浏览器和服务器永远是同一份规则实现。

```bash
node tests/run-checks.js                              # 全部 Node 检查
node tests/run-checks.js --browser                    # 加入真实浏览器发布验收
node --test tests/core.test.js tests/multi.test.js   # 核心规则 + 多人座位/轮换
node server/test-ws.js                                # 自写的 WebSocket 协议
node server/test-rooms.js                             # 房间流程 + 防作弊 + 掉线托管
node server/test-online.js                            # 真 WebSocket 客户端打完整局
node tests/browser-online.js                          # 真浏览器双开联机（需要 Edge，可选）
node server.js 8000
```

详细口径见 [规则与验收](规则与验收.md)，当前任务状态见 [实施记录](实施记录.md)，发布操作见 [发布与回滚](发布与回滚.md)。新版联机前端与服务器应一起更新，动作协议已增加局面版本与请求编号。

服务端已有连接数、房间数、消息频率、消息大小与慢连接输出限制；`GET /healthz` 返回服务版本和汇总计数。默认值、环境变量及 HTTPS 反向代理示例见 [联机服务器说明](deployment/README.md)。这些限制尚不能代替真实公网容量测试。

Node 静态服务支持 gzip 文本压缩。联机后台分析从内联引擎创建 Blob Worker，不引入外部脚本或构建流程。只读线路测试可运行 `node evaluation/check-connection.js https://域名:端口`，不会加入或启动房间。真实公网基线与手机性能的待验收范围见 [联机响应排查](联机响应排查.md)。

### 发布到 GitHub Pages

在线地址：https://2653296079.github.io/mahjong/ 。Pages 使用仓库 `2653296079/mahjong` 的 `main` 分支根目录，所以 `index.html`、`sw.js`、`manifest.webmanifest`、`icon-512.png` 四个文件必须一起留在根目录（`server/` 和 `tests/` 不影响线上运行，也不会被本地服务器对外开放）。

发布前：

1. 跑发布检查：`node tests/run-checks.js --browser`，确认没有漏掉或跳过需要验收的浏览器流程。
2. 本地开 `node server.js 8000`，检查桌面和手机布局、出牌与设置。
3. **改了页面就要把 `sw.js` 里的 `CACHE` 版本加一**，否则已装到主屏幕的离线版会继续用旧页面。

发布：把改动合到 `main` 再推送（`git push origin main`），等 Pages 构建完成再刷新线上页面。Windows 下的 `一键推送到GitHub.bat` 只允许在 `main` 分支运行，在功能分支上会停下，避免误发未审核的改动。
