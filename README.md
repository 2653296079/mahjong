# 转转麻将 · 练牌室

一个可以离线玩的转转麻将练习器。你对战三位电脑玩家，边打边看牌效、公开信息推算的放铳风险，并在每次出牌后看到简短复盘。也可以开一间房，和朋友一起打（人数不够由电脑补位）。支持游客练牌，也可在游戏服务器创建账号，保存自己的完整对局与个人数据。

**在线玩：** https://2653296079.github.io/mahjong/

## 开始

打开后先选「牌效训练」「单机练习」或「联机打牌」。牌效训练先作答，再看向听、有效牌、宽听路线和概率；单机中可返回主界面继续本局。联机返回首页会离开房间。

- 电脑：打开在线地址，或直接用浏览器打开 `index.html`。
- 手机：用 Safari 或 Chrome 打开在线地址，可以添加到主屏幕。竖屏和横屏均可玩。
- 主机入口：Windows 双击 `打开联机麻将.bat`，自动启动或复用服务并打开大厅。

### 三维牌桌（v32）

[在线体验 3D 麻将机](https://2653296079.github.io/mahjong/?build=v32&view=3d&play=1)。首页有「3D 试打一局」，牌局中的「更多」可切换三维牌桌。本机也可双击 `试玩3D麻将.bat` 启动独立预览服务。

使用 Blender 制作的 27 种牌、牌桌、牌背和配件，支持抬牌、摸牌／出牌动画、坐席／俯视切换和拖动空白桌面调整视角。点一下选牌，再点同一张打出；悬停或首次选牌查看原有逐张分析。随时切回二维，可继续当前牌局。详见 [三维试玩说明](三维试玩说明.md)。

麻将机开局包含收牌入机、洗牌、四方升墙、中央掷骰和三轮每家各抓四张。自己的牌翻向玩家、落手排直；三轮后庄家先取一张、隔墩再取一张，其余三家补牌。骰子放大并有近景；大骰定哪家牌墙，小骰定右侧第几墩，文字、金色开口标记和真实取牌一致。结算中点「收牌洗牌 · 下一局」播放下一轮，可随时跳过动画。

三维开局由真人庄家点击「庄家掷骰」后继续，电脑庄家由电脑掷骰。联机同步等待本局庄家，服务器拒绝他人代掷或抢先出牌；断线庄家交由托管。手牌比 v31 放大约两成，抬牌时固定鼠标感应区，避免底缘反复升降。牌旁分析默认显示结论、向听、进张和概率，详细依据与做牌路线点击展开。

轮到你时点击手牌打出。触屏设备需要点两次同一张牌，避免误触；只高亮实际点中的那一张，改点另一张同种牌会转移选择。可碰、杠、胡时操作栏会出现按钮。键盘快捷键：`H` 胡、`P` 碰、`G` 杠、`空格` 或 `Esc` 过。默认不限时；限时模式可在设置中开启。打开弹窗、手机牌况抽屉或切到后台时，倒计时会暂停。

带讲解练牌时，将鼠标移到任意一张可打的手牌上，就会在牌旁显示这张弃牌的向听、有效牌种与未见张数、下一摸概率，以及与推荐弃牌的差距。一向听会补充摸牌后如何调整到较宽听口的路线。键盘 Tab 聚焦、手机第一次点选也可查看；第二次确认才出牌。测验、先判断后反馈或关闭提示时，出牌前不会显示分析。`Esc` 或面板右上角可收起。

打出的牌按实际先后顺序累积在中央牌河。「显示来源」可切换四家不同颜色的外壳，牌面图案不变；也可在设置中立即切换。被碰杠取走的牌移到所属玩家的副露区，中央显示取走张数。手机空间不足时可在各家牌区、中央牌河内滚动查看。

每把结束，结算中会显示四家剩余手牌，先列其他三家，再列自己；碰、杠与收炮的和牌张分开显示。荒庄也能看。关闭后可点「查看本局手牌与结算」重新打开。单机与联机均支持；联机默认在结束约 30 秒后续局，其他玩家也可以提前继续。有人已开始下一局时，旧结算的按钮会变成「返回当前牌局」。

### 牌友头像、背景音乐与教练短句（v34）

三项可以各自关闭的牌桌气质增强，全部由页面自身生成：不加载图片、音频文件或外部字体，离线与单文件约束不变。

- **牌友头像：** 按昵称与座位确定性生成国风线描头像，脸型、发型、胡须、眼镜、头饰、主色与朱砂印七组参数派生，同一局四家不撞脸；只在座位名旁占位，不新增可点击区域。桌面宽度 30–22px 随屏宽降档，窄屏与低高度横屏 16px，三维胶囊内 26px（手机 18px）。默认显示；设置 →「牌友头像」关闭后即时回到纯文字座位。
- **背景音乐：** 原创 D 宫五声音阶，72 BPM、8 小节（约 26.7 秒）循环，筝／笛／木鱼／低鼓全部用 WebAudio 合成；按牌局平静／紧张／收束三档切换，和牌、荒庄有短句收束。默认关闭。设置 →「背景音乐」开启，下一行「音乐音量」独立调节（默认 40，0–100，拖动即时生效）；语音报牌时自动压低音乐，切到后台或隐藏页面即停止，回到前台从新小节继续；关闭「音效」总开关时不创建音频上下文。
- **教练短句：** 等待、答错、点炮风险、鸟牌与复盘五类共 70 条原创短句，用于替换闲置时的等待提示、追加出牌反馈，并在结算里补一行复盘；默认开启，只走可视文本，不写日志、不占用报牌播报通道。设置 →「教练提示」关闭后恢复原文案。本轮不接语音朗读。

体验路径：首页 →「设置」→ 上述三个控件（改动即时生效，「应用并重开」把当前选择写入下一局并持久化）；牌局中「更多」→「设置」同样可达。刷新后按显式白名单恢复，未保存的改动不会生效。

### 仿真拖拽出牌（v41）

轮到你时，可以把任意一张手牌**拖出牌列、放到中央牌河上松手**，直接打出；拖动时牌河会亮起「松手打到牌河」落点提示，松手后这张牌就落到中央牌河。仍在手牌列内拖动时保持原来的理牌行为；点一下选中、再点同一张的二次确认（触屏与三维）不变。二维与三维牌桌共用同一套手牌点击层，所以两种视图都能拖。

### 从牌墙亲手摸牌（v42）

二维牌桌轮到自己时，先不把摸入张直接塞进手里：中央「牌墙」会亮成可点的「牌墙 N 张 · 摸牌」，下方操作栏同时出现「从牌墙摸牌」。点牌墙或按钮后，第 14 张才翻开到手牌最右侧并高亮；摸牌前出牌会被拦下并轻提示，超时会自动替你摸牌。三维牌桌保留原有的「接牌」步骤；二维已摸过的牌切到三维不会再要求接一次。

### 从牌墙拖到手里（v43）

中央「牌墙」也可以直接往手牌方向拖：拖动时会出现一张牌背跟随，靠近手牌列时手牌列亮起金色落点；在手牌列上松手即完成摸牌，第 14 张翻开。拖到别处松手不会摸牌；点牌墙/「从牌墙摸牌」的旧路径仍然保留。手机和桌面共用同一套指针手势。

### 出牌落桌反馈（v44）

二维牌桌每次有人打出新牌，中央牌河的最新一张会带一次短促的落桌回弹（缩放 + 金色描边），桌面同时轻轻一顿；原有按座位方向的滑入保留。该反馈只在二维生效，三维用自己的出牌动画；系统开启「减少动态效果」时不播放。

### 落桌闷响（v45）

二维出牌在原有的点击声之外，落河约 150ms 后补一声低频「闷响」（程序合成，无音频文件），和牌面回弹一起收尾。它走既有的「音效」总开关：关闭音效或页面隐藏时不发声；三维不额外加这一层。

### 碰/杠聚拢（v46）

二维新出现碰或杠时，新增的那组副露会做一次收拢回弹（轻微放大 → 收紧 → 落定，并带一圈金边），已有副露不重排、不重播。三维继续用自身副露摆放和出牌动画；`prefers-reduced-motion` 下不播放。

### 牌河飞向副露（v47）

碰/杠成立时，除了副露本身的收拢回弹，还会从中央牌河位置飞出一张同名牌的牌影，落到新副露上并淡出，补上「被取走的那张从牌河到副露」的视觉路径。只在二维显示；三维继续用自身副露与出牌动画；`prefers-reduced-motion` 下不播放。

### 理牌吸附（v48）

二维手牌支持直接拖动排序：横向拖到另一张牌上时，目标牌的左/右侧会亮起金色插入位，松手后整排手牌按落点重新吸附排列（相邻牌用 180ms 位移回弹，被拖的牌 220ms），并向读屏播报「已把 X 移到第 N 张」（N 是玩家看到的张数）。横向拖动永远不会被当成出牌，只有拖进中央牌河投放区才出牌；贴着手牌上沿的误拖也只会排序。手机 360/390/430 宽度实测 14 张牌全部落在手牌区内、不裁切也不隐藏溢出；`prefers-reduced-motion` 下直接落位不播回弹。三维手牌仍沿用原来的拖拽出牌，不参与二维排序。

### 手机触控与安全区（v49）

竖屏（≤680px）下顶栏操作按钮、摸牌/接牌按钮、更多菜单里的按钮统一到 44px 高，牌墙药丸视觉高度 32px、可点区域向上下各扩 7px（有效高度 ≥44px），点药丸、按按钮或把牌墙拖进手牌都能完成摸牌。顶栏、操作栏、侧栏抽屉和牌桌边距接入四边安全区（`env(safe-area-inset-*)`），刘海屏与手势条不会盖住按钮。360×844、390×844 实测无横向溢出、操作栏贴底且不压手牌。

### 矮横屏触控（v50）

手机横放或分屏（视口高度 ≤500px）时，原来按高度压缩分支会把顶栏按钮压到 28px；现在矮视口同样把顶栏、更多菜单、摸牌/接牌按钮抬到 44px，操作栏保持 56px 高，牌墙药丸在矮横屏隐藏、摸牌改走底部 44px 按钮。844×390 实测无横向溢出、操作栏在视口内、13 张手牌与牌河完整可见。

### 窄屏牌面可读性（v51）

屏幕宽度 ≤400px 时，手牌去掉牌间空隙、把牌加高，让 14 张牌在窄屏上也看得清牌面；选中的那张牌会放大预览（`scale(1.16)`）。这里刻意**不用横向滚动**，因为横向拖动已经被「理牌」占用，加滚动会和拖拽抢手势。360 宽实测单张牌 23.6×46.8、牌面图形宽 19.6；390 宽单张牌 29.8×58.0；两档 14 张都完整落在手牌区内、无横向溢出。三维与联机逻辑不受影响。

> 注意：选中放大的门禁断言曾**不稳定**（连跑 10 次 7 红 3 绿，实测 23.6 → 25.9 即 +9.8%），根因是过渡动画与测量时序；该问题已在 v53 修复，见下节。详见 [v51 验收报告](reports/v51-validation.md)。

### 三维拖牌用真实牌模（v52）

切到三维牌桌后拖动手里的一张牌，跟手的再也不是一张二维牌图片，而是场景里那张真实的牌模：牌被抬起、相邻牌让开插入槽，松手就按槽位重排或打进牌河。三维拖拽到牌河时同样由场景牌模跟随，不再出现二维 ghost。`table-3d-drag` 17 条断言全绿（`tileDrag=5:0`、`tileInsert=14:0:b`、`.drag-ghost` 为空），`table-3d-ui` 45 条回归全绿；中帧截图见 `out\v52-3d-drag-mid.png`。详见 [v52 验收报告](reports/v52-validation.md)。

> 注意：三维拖拽目前只在桌面 Edge（headless 与有头）验过，真实手机 GPU、多人同桌流畅度和拖拽抬升/震动手感**尚未验收**。

### 选中牌放大改用布局尺寸（v53）

窄屏下选中的那张牌不再用 `transform: scale()` 动画放大，而是直接把宽度和高度各放大 16%，并用负外边距抵消加宽、不挤动相邻牌。好处是点选一瞬间就已经是最终尺寸，不会出现「先小后大」过程中被读到中间值的问题。修好之后，门禁里「选中牌宽度放大 ≥12%」连跑 10 次 **10/10 全过**，数值稳定为 23.6 → 27.3（+15.7%）、46.8 → 54.3（+16.0%）；测试页一个字没改，阈值仍是 1.12。详见 [v53 验收报告](reports/v53-validation.md)。

> 注意：v53 出包时完整全量并没有通过——两次都熔断在第 7 组 `table-3d-ui`（三维组），当时**不判全绿**。那次熔断后来由 v54 修复，全量才跑通。真机上的放大效果未验。

### 三维「跳过演出」强制收尾（v54）

三维牌桌在庄家还没掷骰时点「跳过演出」，原来会静默失败：按钮消失、演出没收尾、画面停在旧局，屏幕上一直缺牌。现在改成强制跳过——不管有没有掷骰都会正常收尾，并按新一局的牌面重建桌面，所以点了就能立刻接着打。修完之后，`table-3d-ui` 单跑连跑 5 次全过（修复前是连续 4 次里有 3 次通过、1 次失败），完整全量 `node tests/run-checks.js --browser` 也第一次跑到底：**31 组运行 / 31 组完成 / 失败 0 / 收尾句「全部检查通过」，164.3s**。详见 [v54 验收报告](reports/v54-validation.md)。

> 注意（重要）：**全量通过不等于那个偶发消失了。** 三维早先 14 次单跑里有 5 次失败（约 36%），那批数据跑在干净的原版文件上、是有效的；为什么「单跑会偶发红、满载全量却全过」**至今没有解释**，本次按遗留风险记录，不许写成「已彻底修复」。另外，用来追查它的探针方案已判失败（单次拖到 200 秒超时），`machineBusy` 与演出时序的怀疑仍只是代码推理、**没有实测**；真机（真实手机 GPU、触屏）**完全未验**。

## 和朋友一起打（联机）

1. 打开统一游戏网站，点「联机」，自动连接大厅。
2. 未登录以自动编号的访客身份加入；登录后直接显示注册账号名。
3. 房间号留空创建新桌，或者填写好友的房间号。点「开始对局」即可打牌，空位由电脑补齐。
4. 点击「复制邀请链接」发给朋友。

大厅实时显示在线总人数、已登录账号数和访客数。同账号／访客的多连接各算一人，机器人和诊断探针不算人数。人数推送不会清空正在填写的房间号。

后台联机服务没有启动时自动拉起，已经启动则复用；整个网站入口没有运行时，主机上双击 `打开联机麻将.bat`，自动启动或复用入口并打开大厅。玩家无需处理 IP、端口或局域网设置。原手机入口及 frp 启动脚本也转到统一启动器。

网页和账号入口持续在线，联机进程按需启动。服务崩溃后可自动重新启动，但原局会保留为中断存档，不能无损续打；普通网络断线仍由电脑托管并可重连接回同一局。部署、启动器、统一公网网址配置和截图见 [联机大厅与自动启动](联机大厅与自动启动.md)。

服务器负责发牌、判定和记分，局中只下发自己的暗牌；终局公开四家剩余牌。出牌立即显示等待确认，服务端先回传已确认操作再推进电脑，讲解和风险随后计算。连接状态中仍可查看网络往返和操作确认耗时。

## 账号与个人对局档案

从运行新版 `node server.js` 的游戏地址打开，在首页「登录 / 我的账号」注册。用户名唯一，英文不区分大小写、全角字符会统一处理。登录后新开的单机与联机对局可保存至服务器 SQLite 数据库，按人机和真人同桌分别统计战绩、收支趋势、手动弃牌的基础牌效，并可查看、下载历史完整牌谱。

单机断网时保存待传队列，登录原账号后自动重试。联机由服务器存档，局中不能通过账号接口查看完整暗牌；未完成或中断的对局不计胜率。当前没有忘记密码找回，可凭原密码修改密码。GitHub Pages 和离线文件继续支持游客，账号请从 Node 服务器地址使用。

需要 Node 22.16+；默认数据库在 `data/mahjong.sqlite`，也可用 `MAHJONG_DB_PATH` 指定持久化位置。数据不会随代码提交。归属、统计口径、备份及截图见 [账号与对局存档](账号与对局存档.md)。

| 项目 | 本游戏采用的规则 |
| --- | --- |
| 牌 | 万、条、筒各 1–9，每种四张，共 108 张；没有字牌 |
| 开牌 | 大骰定方：庄家起逆时针，1／5 本家、2／6 下家、3 对家、4 上家；小骰定该家右侧第几墩，1 即第一墩。三轮各抓四张后，庄家取当前墩上层、隔一墩再取上层，其余三家各补一张；四方 14/13/14/13 墩 |

这些是本练习器的牌桌规则，不代表所有地区的麻将规则。

## 练习功能

- **专项与复习：** 先降向听、听得更宽、小七对、数未见牌、副露做牌、碰牌取舍六个主题。36 个基础局面（30 道弃牌、6 道碰／过选择）和 72 道保留变式，共 108 条题目，题库版本 `lessons-v3`。变式首次成绩单独统计；换花色或映射牌号的变式不算新的知识点。错题记录错因，答对后按 1、3、7 天安排复习；记录可导出和恢复。
- **三个实战模式：** 在设置中选择带讲解练牌、先判断后反馈、整局测验。测验期间隐藏答案，结算后查看最多三条基于当时信息生成的关键弃牌回顾。
- **出牌讲解：** 对每个候选弃牌先比较向听，再比较有效进张；列出每种可进的牌及未见张数。一向听时会演示下一摸后怎样弃牌，形成更宽的听口。
- **概率依据：** 在“未见牌随机分布”的简化假设下，下一次自己摸到有效牌的基准概率为 `未见有效张数 ÷ 未见总牌数`。未见牌包含对手暗牌和预留鸟牌，不能当成牌墙中确定存在的牌；对手行动和后续改牌会改变概率。
- **局势分析：** 对对手手牌做随机采样，估计听牌和放铳风险。联机时在后台计算，完成前可先查看基础牌效，失败时可重试。初步模拟评估发现概率偏高，界面提供口径说明；增加采样数不能消除模型假设的偏差。详见 [风险与性能评估](evaluation/README.md)。
- **每手复盘：** 出牌后显示与牌效推荐的差异，以及该张牌的采样风险。
- **防守道场：** 在中后盘局面里练习选弃牌，并比较候选牌的进张与风险。
- **统计和牌谱：** 训练统计保存在当前浏览器的本地存储；本次游戏的牌谱可导出、逐步回放。清除浏览器数据会清除本地统计。
- **离线使用：** 通过 HTTPS 访问后，Service Worker 会缓存页面供离线打开。

## 开发与验证

项目无构建依赖。二维页面、样式、核心引擎和交互代码都在 `index.html`；`server.js` 提供本地静态服务器和联机服务，`sw.js` 提供离线缓存。可选三维视图按需载入 `assets/table3d/`、本地 Three.js 0.180.0 和 GLB 模型，无需 CDN 或 npm 安装；通过 HTTP(S) 使用，直接打开文件时可继续使用二维。

联机的服务端代码在 `server/`，它**不维护第二份引擎**：`server/rooms.js` 启动时直接从 `index.html` 里取出内联的引擎来跑，所以浏览器和服务器永远是同一份规则实现。

```bash
node tests/run-checks.js                              # 全部 Node 检查
node tests/run-checks.js --browser                    # 加入真实浏览器发布验收
node --test tests/core.test.js tests/multi.test.js   # 核心规则 + 多人座位/轮换
node server/test-ws.js                                # 自写的 WebSocket 协议
node server/test-rooms.js                             # 房间流程 + 防作弊 + 掉线托管
node server/test-online.js                            # 真 WebSocket 客户端打完整局
node tests/browser-online.js                          # 真浏览器双开联机（需要 Edge，可选）
node --test tests/atmosphere.test.js                  # 牌友头像 / 背景音乐 / 教练短句静态断言
node tests/no-build-check.js                          # 单文件、零依赖与离线缓存版本
node tests/pages-compat.js table-3d-drag              # 三维牌桌拖拽出牌
node server.js 8000
```

详细口径见 [规则与验收](规则与验收.md)，当前任务状态见 [实施记录](实施记录.md)，发布操作见 [发布与回滚](发布与回滚.md)。新版联机前端与服务器应一起更新，动作协议已增加局面版本与请求编号。

服务端已有连接数、房间数、消息频率、消息大小与慢连接输出限制；`GET /healthz` 返回服务版本和汇总计数。默认值、环境变量及 HTTPS 反向代理示例见 [联机服务器说明](deployment/README.md)。这些限制尚不能代替真实公网容量测试。

Node 静态服务支持 gzip 文本压缩。联机后台分析从内联引擎创建 Blob Worker，不引入外部脚本或构建流程。只读线路测试可运行 `node evaluation/check-connection.js https://域名:端口`，不会加入或启动房间。真实公网基线与手机性能的待验收范围见 [联机响应排查](联机响应排查.md)。

### 发布到 GitHub Pages

在线地址：https://2653296079.github.io/mahjong/ 。Pages 使用仓库 `2653296079/mahjong` 的 `main` 分支根目录，所以 `index.html`、`sw.js`、`manifest.webmanifest`、`icon-512.png` 四个文件必须一起留在根目录（`server/` 和 `tests/` 不影响线上运行，也不会被本地服务器对外开放）。

发布前：

1. 跑发布检查：`node tests/run-checks.js --browser`，确认没有漏掉或跳过需要验收的浏览器流程。
2. 本地开 `node server.js 8000`，检查桌面和手机布局、出牌与设置。
3. **改了页面就要把 `sw.js` 里的 `CACHE` 版本加一**，否则已装到主屏幕的离线版会继续用旧页面。

发布：把改动合到 `main` 再推送（`git push origin main`），等 Pages 构建完成再刷新线上页面。Windows 下的 `一键推送到GitHub.bat` 只允许在 `main` 分支运行，在功能分支上会停下，避免误发未审核的改动。
