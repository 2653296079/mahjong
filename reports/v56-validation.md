## 9. 验收后追加：截图未取得的原因（重要）

> 本节于验收当天追加，依据是送验方（码仔）的实测回传与验牌对源码的核实；**不改变 §1 的三轮结论**，只把「截图未取得」的原因说准确。

### 9.1 根因：提示在翻牌那一刻就消失，玩家看不到

`index.html` = `2685FF952AA34B7B`（598465B）实测代码路径：

```
3026-3031  drawPending2D() = … && !!handArrange.drawn && !handArrange.revealed
3041       acceptDrawnTile() 第一行即 handArrange.revealed = true
5402       renderCenter: drawable = drawPending2D()
5404-5418  if (drawable) 才写「本次第 N 次摸牌」
5419-5426  else 写回「牌墙 N 张（约 N 巡）」
```

即：**点一下「摸牌」，接牌与翻牌在同一帧完成，`wallInfo` 立刻切到非 drawable 分支**，「本次第 N 次摸牌」几乎不可能被玩家看到。送验方实测回传 `wall="牌墙 49 张（约 12 巡）"`、`handAfter1=14`，与该路径一致。

### 9.2 因此截图一项应记为「功能未达成」，不是「未取得」

- 「未取得」容易被理解为取证方法/环境问题；
- 实际是**呈现本身不成立**——玩家看不到这段文案，换任何截法都截不到有意义的画面。
- **门禁为什么是绿的**：`tests\draw-nth.test.js` 的 9 条断言测的是 `drawNthOf` 的**算法正确性**（`(head-head0)+tail`、下限 1），算法确实对；**没有任何断言覆盖「这段文案玩家看不看得见」**。这正是 §7.1 所述缺口的具体实例。
