# v48 验证报告：理牌吸附与误触防护

日期：2026-11-07。BUILD `v48`。范围：二维手牌的拖动排序手感；三维与联机逻辑未改动。

## 实现摘要

- **插入位吸附**：拖动手牌经过另一张牌时，按指针落在目标左/右半边决定插入侧；目标牌内侧描边 + 手牌行内绝对定位的金色竖条（3px、外发光、120ms 出现动画），松手即按该侧落位。
- **松手回弹**：`moveHandTile` 前后记录每张牌的 `getBoundingClientRect`，用 WAAPI 做 FLIP（其他牌 180ms、被拖牌 220ms，`cubic-bezier(.2,.8,.3,1)`）；`prefers-reduced-motion` 下不做动画。
- **误触出牌防护**：二维拖拽只有在指针高于手牌区上沿 16px 且进入中央投放区时才判为出牌；手牌区内、以及贴着上沿的横向拖动一律只排序。三维沿用原有判定。
- **读屏播报**：排序后向 `#announce` 写入「已把 X 移到第 N 张」，N 取玩家看到的 DOM 顺序（含末尾摸入牌），2 秒后自动清空。
- **键盘路径复用**：Alt+←/→ 仍走 `moveHandTile`，因此同样获得回弹与播报。

## 窄屏策略核实

用探针在 v47 上实测（14 张已摸入）：390×844 单张 24.5×42.9、360×844 22.3×39.6、430×932 27.3×47.3，末张右缘均在手牌区内且 `scrollWidth = clientWidth`，即当前并不存在路线文档里写的「390 横向溢出」。本轮因此确定策略为**缩放全部可见**，不引入横向滚动；360 下 22px 牌宽偏小属于可读性议题，留待单独评估。

4. 贴手牌上沿横拖：不点亮牌河、松手不出牌、仍落到目标左侧。
5. 拖进中央：点亮投放区、松手弃牌 +1、提示收起。

## 本轮修正记录（都是测试/时序问题，未放宽断言）

- fixture 把 `lastDraw` 写成 `practiceHand()` 的返回值，摸牌按钮不出现 → 改为与 `selection-ui` 一致的 `lastDraw = 0`。
- 读屏断言写死「第 7 张」，实际可见位置是第 8 张（前面还有摸入牌）→ 把产品播报改为按 DOM 可见下标计算，断言按同一下标推导，不写死数字。
- 左侧插入的下标关系写反 → 左侧为「源牌下标 = 目标下标 − 1」。
- 测试页忘了置 `out.ok = true`，步骤全过仍判失败 → 补上。
- 截图里金色竖条不可见：竖条有 120ms 出现动画，截图在动画 0% 时抓到 opacity 0 → 采样像素定位后，把截图等待延长到 340ms；产品代码无需改动。
- 全量 `--browser` 前三次在首组 `table-3d-ui` 卡住（单跑 38s 通过）：一次硬超时、两次停在「机器就绪但只投影 13 张」。诊断出三层超时没对齐（pages-compat 自检 100s < Edge 子进程 120s < 测试内部 180s），已改为自检 200s、子进程 220s、run-checks 300s 并打印每组耗时；另在 3D 验收里加「就绪后卡 5s 就派发 resize 触发重绘」的恢复等待。第 4 次全量 23 组 0 失败，`table-3d-ui` 38s、恢复逻辑未触发。卡住的根因（满载/软件渲染下最后一帧投影未刷新）尚未定论，只记录为已知偶发，不影响产品断言。

## 未做 / 已知限制

- 三维手牌不参与二维排序（3D 用投影 hitbox，排序会与投影坐标冲突），仍只支持拖拽出牌。
- 手牌横向滚动未实现：实测不需要；若后续要提高 360 下的牌面可读性，可再评估「最小牌宽 + 滚动」策略。
- 排序不写入牌谱：牌谱记录出牌顺序，理牌只是本地视图顺序，刷新/下一巡按手牌种类重建。
