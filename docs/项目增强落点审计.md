## 0. 摘要（先看这 8 条）

1. **代码边界比注释更硬**：整页只有 3 个 `<script>`（`index.html:749-2518` 引擎、`2519-5773` 界面、`5774-5778` sw 注册）。引擎被**三种不同规则**抽取复用：`tests/core.test.js:8-12` 按 UMD 起止切片、`server/rooms.js:20-30` 取**第一个** script 全文、`index.html:3236` 取 `#mahjongCore` 的 `textContent` 做 Worker。新增代码放错位置会同时打穿 Node 测试、联机服务与浏览器后台采样。
2. **AI 差距是「参数同质」，不是「算法缺失」**：已有 v1 启发式、v2 采样风险、v3 弃和三套，但关键旋钮全是全局量——`RULES.winGain/riskWeight`（`781-790`）、`aiWinDecision` 过胡门槛（`2229-2231`）、碰牌只看牌效（`2235-2239`）、胡不胡由全局 `opts.aiStyle` 决定（`1810/2219`）。座位只带一个 `aiStyle` 字符串（`1818-1821`），没有性格数据的落点。
3. **音效差距是「事件缺位」**：`sfx(kind)` 只有 5 类（`3146-3157`），`'draw'` 从未用于摸牌，只在防守道场被复用成「答对」提示（`4839`）——语义错位；`sfxSig.drawn` 声明未用（`3159`）。摸牌、碰/杠分家、轮到你、骰子/发牌、翻鸟、答错全都没有声音。
4. **音效靠 `render()` 的状态签名驱动**（`3082-3100`、`3160-3179`）：快进（`2969-2984`）与 3D 演出期间（`2945-2946`）`render` 不逐手调用，多手会「静音」；反过来 3D 已提供 `onDice/onPacket/onBusy`（`2666/2672/2675`）这类更准的音频挂点。
5. **报牌（语音）完全空白**，且**不能**把文案塞进 `#hint/#coach/#miniHint`：考试/反馈模式的文字断言很密（`tests/training-release.html:17-18、36-39`、`tests/coach-advice.html:36`）。报牌走独立通道（纯音频或新增 `#announce`）才安全。
6. **性格系统的最小侵入主线**：纯数据表 + 每座位参数，放在**引擎内**（`PERSONA` 表 + `personaOf(seat)`），座位字段 `G.seats[i].persona`；`opts.personas` 缺省 `null` 时所有分支短路，默认路径与今天**逐字节一致**；**绝不消耗牌墙 RNG**、**绝不用 `Math.random()` 做决策**。
7. **音效/报牌的最小侵入主线**：只改 game.js，用 `H.record.events` **事件游标**驱动（引擎零改动、快进也覆盖），保留旧 `sfx(kind)` 签名向后兼容；TTS 默认关、静默降级、独立 `#announce`。
8. **五个最高危回归点**（§8 详述）：① `sw.js` 缓存版本与 `tests/offline.test.js` 的期望数组联动；② 新 `<script>` 插在引擎脚本之前 → `loadCore` 取错脚本；③ 引擎脚本里出现 DOM/WebAudio 依赖 → Node vm / loadCore / Worker 三处崩；④ `.seatName` 里禁止出现 `<b>` 且节点结构被测试锚定；⑤ 考试/反馈模式的文字泄漏与 `coachMain` 正则。另加两条次级风险：设置面板 id 契约、3D 全流程 2000 步性能。

### 6.2 默认如何关闭（零行为变化的证明方式）

3. `cfg.personaSet` 默认 `'off'`，`newGame` 只在非 `off` 时传 `personas`。
4. **不消耗牌墙 RNG**：persona 分配若需要随机性，用独立确定性函数 `hashName(name) % PERSONA_IDS.length`，或 `mulberry32(seed ^ 0x9e3779b9)` 另起一条流；绝不调用 `G` 内部的 `rng`（`1808`）。
5. **不用 `Math.random()` 做决策**（现有 `sfx` 的 ±10% 抖动只在音频层，`3151`）。
6. 不改变 `analyzeSituation` 的 seed 公式（`2254`）、不改变 `evaluateDiscards` 的排序与 `RULES` 常量（`2267`）。
7. 保持 `G.setAiStyle(seat, style)` 可用（`2362`，`settlement-ui.html:42` 依赖）。

## 7. 设计 B：音效/报牌（最小侵入）

### 7.1 分层

```
引擎（不动） ──► H.record.events / H.lastDiscard / H.result   （已有公开事件）
   │
game.js
   ├─ 合成器：sfx(kind) 表驱动（扩展 3146-3157，保留旧 kind）
   ├─ 事件游标：sfxTick() 读 record.events 增量（新增，替换/兼容 sfxCheck 3160-3179）
   └─ 报牌：announce(text, persona)（新增，TTS，默认关）
```

### 7.2 事件游标（推荐，替代扩展 `sfxCheck`）

- 游标：`var sfxCursor = { handNo: -1, n: 0 }`。
- 每次 `render()`（`3091`）调用 `sfxTick()`：若 `game.handNo !== sfxCursor.handNo` 重置；取 `H.record.events.slice(sfxCursor.n)`，按 `t` 映射：
  - `t:'d'` → 摸牌音。**只有 `s === game.humanSeat()` 时**才允许后续报牌念牌名；对手摸牌只出声、不报牌（`record.events` 里对手摸牌的 `k` 是真实牌种，见 `1901`，播出去就是泄底）。
  - `t:'x'` → 弃牌音（可按座位音高微差）。
  - `t:'p'` → 碰音；`t:'g'` + `y` → 暗杠/明杠/补杠三种音。
  - `H.over` → 自摸/收炮/荒庄/点炮（用 `H.result.winners.indexOf(hs)`，与现有 `3174-3176` 一致）。
- 联机降级：代理 `P.hand` 没有 `record`（`5408-5425`），`sfxTick` 回落到现有签名逻辑。
- 限流：一次 `slice` 中事件 > 3 条时，只播最高优先级的 1-2 条（胡 > 杠 > 碰 > 弃 > 摸），并跳过中间音；快进（`2969-2984`）时只播结算音。
- 优点：引擎零改动；`sfxCheck` 的 `drawn`/`meld` 计数缺口一并修好；`evaluation` 的 `engineSha256` 不变。

### 7.3 音效类别（≥10，全部程序合成）

|---|---|---|---|
| `discard` | 任一 `t:'x'` | 现有 `3152` | 保留 |
