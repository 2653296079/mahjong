## 3. 设计 A：对手性格系统

### 3.1 设计原则

1. **一套 AI + 一层参数**：不新写第四套搜索。只把性格换算成 `riskMul / pengBias / huPass / huNeed / fold / defenseFrom / follow / paceMul`，注入现有 `aiDiscardEval`、`aiPengDecision`、`aiWinDecision`、`aiDiscard` 和 UI 延时。
2. **性格与难度正交**：`cfg.aiStyle`（v1/v2/v3）仍是“算力/强度”轴；性格只调“倾向”。性格不改变采样组数、不改变 `RULES`，不改变牌墙/发牌。
3. **默认中性**：`opts.personas` 缺省 `null`；座席**不写入** `persona` 字段（不是 `null` 字段，而是没有该属性），所有分支 `if (pp)` 短路。
4. **确定性**：性格分配只用名字哈希/固定表，不调用 `Math.random()`、不消耗 `mulberry32` 牌墙流；同 seed + 同 personas → 牌谱逐字节可复现。
5. **无暗牌读取**：性格参数只乘在现有分数/门槛上；`aiDiscardEval` 仍只通过 `analyzeSituation` 的公开投影看对手，绝不读 `H.players[对手].concealed`。
6. **可解释**：标签+说明文字能对应到参数，不做“随机乱打”。

### 3.2 六种性格总表

所有值都只在本轮实现中生效；“中性”= 不启用性格时的行为。标签固定 2 个汉字，`desc` 用于 `title`。

| id | 名称/标签 | 一句话 | riskMul（弃牌风险） | pengBias（鸣牌） | huPass / huNeed（胡牌） | fold（弃和） | defenseFrom（v1 防守） | follow（跟打） | paceMul（节奏） |
|---|---|---|---|---|---|---|---|---|---|
| `steady` | 稳健 | 先保听牌，不轻易冒险 | 0.70 | -1 | false / 0 | false | 12 | false | 1.20 |
| `raider` | 猛攻 | 有碰就碰，抢速度 | 1.50 | +1 | false / 0 | false | 4 | false | 0.75 |
| `turtle` | 龟缩 | 宁可不听，也不点炮 | 0.45 | -1 | false / 0 | true | 14 | false | 1.30 |
| `gambler` | 赌徒 | 小胡看不上，敢放过 | 1.30 | +1 | true / -2 | false | 6 | false | 0.90 |
| `mimic` | 跟打 | 盯着上家，跟同花色 | 1.00 | 0 | false / 0 | false | 10 | true | 1.00 |
| `schemer` | 算计 | 只按牌效，精打细算 | 1.00 | 0 | true / +1 | true | 8 | false | 1.10 |

### 3.3 每种性格的决策参数与可观察差异

#### steady · 稳健

- **标签/说明**：`稳健`；`先保听牌，不轻易冒险`。
- **弃牌**：`riskMul=0.70`（放铳风险权重降到 70%）；v1 下 `defenseFrom=12`（比默认 10 更早转守）。
- **鸣牌**：`pengBias=-1`（只在向听真的变好时碰；进张变多但向听不变不碰）。
- **胡牌**：`huPass=false` → 有胡就收（等同默认 `greedy`）。
- **可观察**：同一 seed 下副露次数低于中性；危险牌弃出更少；AI 行动延时约为默认的 1.2 倍。
- **默认关闭时**：不分配该 id；座席无 `persona` 字段；走原 `aiDiscard/aiPengDecision/aiWinDecision` 分支。

#### raider · 猛攻

- **标签/说明**：`猛攻`；`有碰就碰，抢速度`。
- **弃牌**：`riskMul=1.50`；v1 下 `defenseFrom=4`（很晚才防守）。
- **鸣牌**：`pengBias=+1`（有碰就碰，抢速度；不再比较碰后进张）。
- **胡牌**：`huPass=false` → 有胡就收。
- **可观察**：副露次数最高；危险牌比例更高；AI 行动明显更快（约 0.75 倍）。
- **默认关闭时**：同上，不分配、无字段、原分支。

#### turtle · 龟缩

- **标签/说明**：`龟缩`；`宁可不听，也不点炮`。
- **弃牌**：`riskMul=0.45`；`fold=true`（v2 也把“最安全的 3 张”纳入候选，允许牺牲向听）；v1 下 `defenseFrom=14`。
- **鸣牌**：`pengBias=-1`（只在向听真的变好时碰）。
- **胡牌**：`huPass=false` → 有胡就收。
- **可观察**：副露最少；更常打安全牌、平均危险度最低；AI 行动最慢（约 1.3 倍）。
- **默认关闭时**：同上，不分配、无字段、原分支。

#### gambler · 赌徒

- **标签/说明**：`赌徒`；`小胡看不上，敢放过`。
- **弃牌**：`riskMul=1.30`；v1 下 `defenseFrom=6`。
- **鸣牌**：`pengBias=+1`（有碰就碰）。
- **胡牌**：`huPass=true, huNeed=-2` → 采用实验性过胡公式，且门槛比默认低 2 巡，宽听且巡目足时更常放过小胡。
- **可观察**：能胡时偶尔不胡（过胡）；副露偏多；节奏略快。
- **默认关闭时**：同上，不分配、无字段、原分支。

#### mimic · 跟打

- **标签/说明**：`跟打`；`盯着上家，跟同花色`。
- **弃牌**：`riskMul=1.00`；`follow=true`：在“同向听最优候选集”里，如果有与最近一手弃牌**同花色**的候选，只在该子集里按 EV 选；没有则按原 EV。
- **鸣牌**：`pengBias=0`（等同默认）。
- **胡牌**：`huPass=false` → 有胡就收。
- **可观察**：弃牌花色频繁跟随最近一手（上家/上一张）；其他指标接近中性；节奏不变。
- **默认关闭时**：不分配该 id；座席无 `persona` 字段；`follow` 不读取；走原分支。

#### schemer · 算计

- **标签/说明**：`算计`；`只按牌效，精打细算`。
- **弃牌**：`riskMul=1.00`；`fold=true`（v2 也允许弃和候选）。
- **鸣牌**：`pengBias=0`。
- **胡牌**：`huPass=true, huNeed=+1` → 比默认更不愿意过胡（更常收下小胡），但仍会在极宽听时尝试。
- **可观察**：比中性能更早弃和；过胡次数少于赌徒；节奏略慢。
- **默认关闭时**：同上，不分配、无字段、原分支。

### 3.4 参数语义（实现必须按此公式）

设 `pp = personaParams(seat)`；`pp === null` 时以下全部跳过，执行原文。

| 参数 | 作用点 | 精确规则 |
|---|---|---|
| `riskMul` | `aiDiscardEval`（v2/v3，`2267`） | `LOSS = RULES.riskWeight * pp.riskMul`；`GAIN` 不变；不改采样 seed 公式（`2254`） |
| `fold` | `aiDiscardEval` 的 `allowFold` | 有 pp 时取 `pp.fold` 或 `seat.aiStyle==='v3'`，无 pp 时取 `seat.aiStyle==='v3'`；仅当 `minSh>=1` 时追加安全牌候选（沿用 `2260-2264`） |
| `defenseFrom` | `aiDiscard` v1（`2290`） | 仅 v1：`if (best.shanten >= 2 && left <= pp.defenseFrom)` 才进入安全牌排序；默认阈值 10 |
| `pengBias` | `aiPengDecision`（`2235-2239`） | `advice = pengAdvice(...)`；`0` → `!!advice.better`；`+1` → 有对子就碰（“有碰就碰”）；`-1` → 只在 `after.shanten < before.shanten`（向听真的变好）时碰 |
| `huPass` / `huNeed` | `aiWinDecision`（`2218-2233`） | `pp.huPass===false` → 直接 `return 'hu'`；`true` → 走现有 `need` 公式，最后 `need += pp.huNeed`；`threat>=2` 的 `+2` 保留；`outs>=2 && left>=need` → `pass`，否则 `hu` |
| `follow` | `aiDiscardEval` 候选集 | `set` 生成后，若 `H.lastDiscard` 存在且 `set` 中有 `suitOf(o.kind)===suitOf(H.lastDiscard.kind)` 的候选，把 `set` 过滤为该子集（至少 1 个才过滤），再按原 EV 选 |
| `paceMul` | `tick()` 的 AI 行动延时（`3017-3024`） | `delay = clamp(cfg.aiThink * pp.paceMul, 0.4, 2.0)` 秒；仅 AI 行动；人类时限、碰杠胡 `pendingResolve` 延时（`2986-2991`）不变 |

**算法覆盖矩阵**（诚实说明，避免实现者误以为 v1 也受 `riskMul` 影响）：

- `primeSpeech()`：`getVoices()` + 监听一次 `voiceschanged` 刷新缓存；只在音效总开关开启且 `cfg.voice!=='off'` 时由 `unlockAudio`/`btnApply` 预热。**报牌依赖音效总开关**：`cfg.sound=false` 时既不建 `AudioContext`，也不预热 TTS；设置项文案已注明「需音效开启」。
- 取消时机（实际）：新一局（`newGame`/`handNo` 变化）、页面 `visibilitychange` 隐藏（或 `document.hidden` 被发现）、`cfg.voice` 改为 `off`、`cfg.sound` 改为 `false`（后两者强制 `cancelAnnounce(true)`）。**不在结算面板出现时取消**，否则刚开口的「你胡了/荒庄」会被吞掉；结算面板出现前已由 `sfxCheck` 报完。
- `cancelAnnounce(force)` 只在 `force || cfg.voice!=='off' || 确有活动 utterance/队列` 时调用 `speechSynthesis.cancel()`；默认 `voice=off` 时不会产生无谓的 cancel。
- 页面隐藏：`sfx`/`announce`/`sfxCheck` 三个入口都检查 `document.hidden`；`sfxCheck` 隐藏时把事件游标推进到末尾、记录结算 key 与当前 `awaiting`，但不发声、不写 `#announce`、不 `speak`；恢复可见后从当前位置继续，**不补播**隐藏期间的事件。
- 考试/反馈模式：报牌只报事实，不参与建议；`training-release.html` 的文字断言不得被 `#announce` 影响（它不在 `#coach/#hint/#miniHint` 里）。

## 10. 附：术语与边界

- **中性**：不启用性格（`opts.personas` 缺省 / `cfg.persona='off'`）。中性不是第 7 种性格。
