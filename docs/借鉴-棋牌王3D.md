1. **人设不是“几套 AI”，而是“一套 AI + 一层参数”**：18 个原型 × 9 个 0..1 性格维度，叠加头像固定性格与难度校准，再叠加每局从 14 套“打法”中抽 1 套（六成沿用本命打法）。`apk/assets/www/js/core.js:362-426`、`apk/assets/www/js/mj.js:731-753`

3. **声音是“三层总线 + 事件表”**：音效/语音/音乐独立音量；约 50 个实时合成音效按事件触发；语音是预制 5 音色、按角色映射并随倍速变调；没有对应语音时直接静默。`apk/assets/www/js/audio.js:9-33`、`:55-131`、`:173-258`
4. **报牌只在关键节点**：出牌报牌名，吃/碰/杠/胡各喊一句；2 倍速以上不报牌，事件积压时整体静音，避免叠成一片。`apk/assets/www/js/t3-mj.js:229`、`:306`、`:315-316`、`:341-342`
5. **3D 不在网页层**：网页只把镜头和物体位置拼成数值帧交给原生 Vulkan；网页负责透明 overlay、镜头、把 DOM 贴到 3D 投影点、事件编排。`apk/assets/www/index.html:13`、`apk/assets/www/js/t3-core.js:3-6`、`:866`
6. **交互是“点选→再点出牌”**：拖动留给镜头，双指缩放/平移；按钮只显示当前合法动作，并贴着牌桌投影位置。`apk/assets/www/js/t3-core.js:635-687`、`apk/assets/www/js/t3-mj.js:508-524`
7. **牌桌演出有明确“叙事顺序”和时长表**：收牌→升墙→推近掷骰→按点数开门→四张一轮抓牌；倍速统一缩放等待。`apk/assets/www/js/t3-mj.js:268-291`、`apk/assets/www/js/mj.js:969-981`
8. **不建议照搬**：运势改未见牌、统计表、规则变体、预制语音资产和全部文案。它们要么有公平性风险，要么与单文件离线约束冲突。`apk/assets/www/js/mj.js:307-360`、`apk/assets/www/js/core.js:490-546`

### 1.2 3D 由原生渲染的确认

- 网页 HTML 直接说明：3D 画面在网页下面，网页是透明的，只叠界面。`apk/assets/www/index.html:13`
- 公共 3D 层注释：每一帧把镜头和所有东西的位置拼成一串数字，交给原生 Vulkan 渲染器 `N3D.frame`。`apk/assets/www/js/t3-core.js:1-6`
- 实际发送点是 `N.frame(str)`，且只在数值帧字符串变化时才发送，减少跨桥调用。`apk/assets/www/js/t3-core.js:825-866`
- 原生在切后台/回前台时回调网页侧 `T3D.pause`，网页相应地停语音、挂起音效。`apk/assets/www/js/t3-core.js:982-983`
- 本次解包目录只保留了 `assets/` 与 `AndroidManifest.xml`，原生库/渲染器不在可见范围，也未做原生逆向；但网页层没有任何 3D 渲染实现（没有 WebGL 画布、没有着色器、没有模型加载），足以确认“网页 = 透明 overlay + 数值帧生产者”。

**推论**：这本 APK 可借鉴的 3D 经验，重点不是渲染技术，而是**编排、镜头、投影 UI、事件节奏与性能闸门**。本项目已有独立的 `assets/table3d/table3d.js`（three.js + GLB，712 行），不应为了“像它”重写 3D。

### A. 对手性格系统（最高优先）

#### A1. 人设原语：9 个 0..1 维度 + 18 个原型 + 微抖动 + 难度校准

**证据**
- 人设维度：进攻、挑牌、诈唬、防守、贪大、走眼、爱吃碰、爱长考、爱秒出；另有手速 `tempo`。`apk/assets/www/js/core.js:362-368`
- 18 个原型（铁公鸡、疯子、老江湖、新手、跟到底、赌徒、慢性子、急性子、戏精、计算器、上头王、胆小鬼、做大牌的、磨王、凭感觉的、老狐狸、莽夫、稳当人），每个原型带一整套数值。`apk/assets/www/js/core.js:369-388`
- 坐下时抽一个原型，每个维度再加 ±0.15 的随机浮动，所以同一原型两个人也不一样。`apk/assets/www/js/core.js:392-399`
- 头像自带固定性格（`STYLE` 表，-0.8…0.9）会再掺进进攻/防守；难度只缩放“走眼”程度。`apk/assets/www/js/core.js:389`、`:396`；`apk/assets/www/js/chars.js:37-42`
- 真人与托管玩家使用中性人设（不走眼、不拖时间）。`apk/assets/www/js/core.js:390`、`:408-412`

**机制**：把“像谁”（性格）和“多强”（难度）分成两条正交的轴。难度只影响计算精度/前瞻/失误，不改变性格倾向；头像/角色则提供可记忆的固定底色。这样同一难度下不同对手仍然可区分。

**原创实现要点**
- 设计 7 个自有维度：`进攻性 / 副露欲 / 守备心 / 贪大 / 情绪波动 / 手速 / 粗心`，全部 0..1；不要照搬 9 维名称与原型。
- 6–8 个自有原型即可（例如“稳手、抢攻、门清、守门、随性、做大、慢郎中、快手”），每个原型用一小组数值定义，再叠加 ±0.12 抖动。
- 头像/席位可以绑定“固定底色”，但不要复制对方角色与头像；可以用本项目已有的简洁头像 + 文字标签。
- 关键约束：**默认人设必须是“标准/中性”**，其参数等于现有 AI 行为，保证既有测试与强度基线不变。
- 用种子随机（现有 `cfg.seed` 思路）保证同种子同对手，便于复盘与测试。

**风险**：难度与人设双重影响容易失衡；默认人设不中性会让基线回退。缓解：默认中性、性格只调“倾向”不调“算力”、用固定种子做对比测试。

#### A2. 打法池 × 本局计划：从“性格”落到“这局想怎么打”

**证据**
- 麻将登记了 14 套打法，每套有：远/中距离吃碰意愿、吃牌系数、忍不住吃碰的概率、做清一色/碰碰胡/七对的倾向、防守权重、是否后半局才防守、走眼噪声、先打哪种牌。`apk/assets/www/js/mj.js:731-753`
- 每套打法的抽中权重是人设的函数（例如爱吃碰的人更容易抽到“见牌就吃”）。`apk/assets/www/js/mj.js:738-752` 的 `w` 字段；抽取逻辑在 `apk/assets/www/js/core.js:400-404`
- 坐下先抽一套“本命打法”；每局有六成机会继续用本命，否则重抽；同一局内固定。`apk/assets/www/js/core.js:415-426`
- 局内再生成“本局计划”：根据手牌决定做清一色/碰碰胡/七对；打了七八张还差得远就放弃大牌、回到平胡。`apk/assets/www/js/mj.js:754-772`
- 计划会转成对每张牌的“习惯偏移”：做清一色时异门牌更愿意打、做碰碰胡时对子舍不得打。`apk/assets/www/js/mj.js:774-784`

**机制**：三层随机——**人设（长期）→ 本命打法（跨局）→ 本局计划（局内）**。这样对手既有稳定印象，又不会每局一个样；同时“做不成会放弃”避免了 AI 一条路走到黑。

**原创实现要点**
- 打法卡片参数控制在 6–8 个，全部命名自有；每个原型只给 2–4 张高权重卡片，避免“谁都能抽到所有风格”。
- 本局计划在发牌后计算一次，存 `{handNo, plan, committedAt}`；每摸 3 张复核一次，超过阈值就放弃。
- 把“计划”做成可观察的：做大牌时偶尔冒一句“这把想做大的”（原创短句），输赢后不一致的反应会更像人。
- 权重函数保持纯函数，输入 `(persona, difficulty, handNo)`，输出卡片；便于单测。

**风险**：风格太多会让对局不可预测、训练体验变差。缓解：限制同时生效的“强倾向”数量（例如清一色与七对互斥），并在设置里提供“性格强度：关/弱/标准”。

#### A3. 性格落到决策的四个旋钮：吃碰、做大、防守、噪声

**证据**
- 弃牌评分 = 向听/进张基础分 + 习惯偏移 + 噪声；噪声 = 人设走眼 × 系数 + 打法噪声。`apk/assets/www/js/mj.js:792-812`
- 防守权重 = 难度基础 + 打法防守 × 人设小心程度 × 阶段系数（先攻后守的人后半局才认真防）。`apk/assets/www/js/mj.js:795-798`
- 非地狱难度按向听数给风险加权：离胡越远越不冒险（向听 ≥2 权重 420、1 权重 140、听牌 35）。`apk/assets/www/js/mj.js:813-820`
- 叫牌（吃碰杠）不只看向听，还看：本局计划（七对不吃碰、清一色不要异门）、远/中距离的意愿门槛、吃牌系数、`loose`（没用也想碰）、`late`（后半局收手）。`apk/assets/www/js/mj.js:893-916`
- 神级在离胡远且别家多半听牌时直接不碰不吃，留安全牌防守。`apk/assets/www/js/mj.js:880-885`

**机制**：不是给每个性格写一套算法，而是**同一套评分/门槛，换参数**。这样强度可控、可测试，也避免“性格 = 随机乱打”的刻板印象。

**原创实现要点**
- 保留本项目现有 `aiDiscard` 的 v1/v2/v3 作为“强度档”，在其上注入 `persona` 参数；不要新写第四套搜索。
- 四个旋钮即可：`claimBias`（吃碰门槛）、`bigHandBias`（做大的概率）、`defenseBias`（危险牌权重）、`noise`（同分随机）。
- 公式用本项目自己的量纲（向听、有效张、放铳概率），不要复制对方的表与系数。
- 加一条“可解释性”：调试面板能显示某座位当前人设、本局计划、本回合各旋钮值，便于教练/复盘解释。

**风险**：性格影响叫牌会改变牌局长度与和牌率；如果用于考试/评估，会引入噪声。缓解：训练模式可固定人设，评估模式默认“标准”。

#### A4. 情绪记忆：输多了会上头，赢多了会手热

**证据**
- 每个机器人按本局净输赢（以底分为单位）平滑出情绪值；激进的输多了更猛，稳健的输多了更怂；难度越高情绪影响越小。`apk/assets/www/js/game.js:136-154`
- 情绪值叠加到头像固定性格上，得到“当前打法松紧”。`apk/assets/www/js/chars.js:41-42`
- 情绪触发台词：上头、害怕、手热；同一机器人 3 局内不重复说。`apk/assets/www/js/game.js:151-152`
- 结算后赢家得意、输家抱怨、观众送花/点赞，甚至互相扔道具。`apk/assets/www/js/game.js:253-288`

**机制**：情绪是**跨局、慢衰减、有上限**的状态，只影响倾向，不影响发牌；且用“3 局冷却”防止复读。

**原创实现要点**
- 状态只需两个：`tilt`（负 → 更攻/更莽）与 `confidence`（正 → 更稳/更敢做牌），每局按净分更新、按 0.7 衰减、夹在 ±0.4。
- 情绪只改 A3 的旋钮，不改摸牌/发牌；绝不复制对方的“运势改未见牌”。
- 台词用原创短句池（每类 4–6 句），按座位节流；无语音时只显示气泡。
- 给用户一个“对手情绪”开关；训练复盘时可关闭，避免被情绪噪声干扰。

**风险**：连续输赢会形成“滚雪球”或被玩家感知为针对；公平性存疑。缓解：严格夹上限、评估模式关闭、明示“情绪只影响倾向”。

#### A5. 思考节奏：快出、长考、走神都是人设的一部分

**证据**
- 思考时间 = 基础时长 × 手速 × 当前状态 × 对数正态抖动；再按“爱秒出/爱长考”的概率覆盖为 170–400 ms 或额外 0.9–2.6 s；另有 5% 走神。结果夹在 150–4600 ms。`apk/assets/www/js/core.js:430-448`
- 麻将机器人：摸什么打什么时快（约 380–800 ms），换牌 600–1450 ms，杠/胡 800–1500 ms；打到后半局会多看一眼。`apk/assets/www/js/mj.js:984-991`
- 长考时会偶尔嘀咕一句，由 `PK.Think.last === 'tank'` 触发。`apk/assets/www/js/mj.js:989`
- 计算耗时从思考时间里扣，避免“算得越久等得越久”。`apk/assets/www/js/mj.js:986-990`

**机制**：先估一个“一般人要多久”，再按人设与这一步的难度加工；**计算时间计入预算**，所以慢 AI 不会额外拖慢。

**原创实现要点**
- 提供 `thinkDelay(persona, kind)` 纯函数，返回毫秒；`kind` 取 `snap / normal / hard`。
- 机器人的同步计算包在 `performance.now()` 里，从延迟中扣除；测试环境把延迟设为 0。
- 本项目现有 `cfg.aiThink` 可保留为“全局倍率/上限”，人设只在其内浮动；避免新增一个不受控的定时器。
- 长考时显示“思考中…”气泡而不是阻塞 UI；玩家可以继续看牌/使用教练。

**风险**：定时器让测试不稳定、让快节奏玩家烦。缓解：纯函数 + 可注入时钟；默认时长上限 1.2 s；2 倍速下按比例缩短。

#### A6. 性格要能被看见：徽章、气泡、动作、表情

**证据**
- 座位牌显示难度徽章（简/般/难/狱/神），并按难度给颜色。`apk/assets/www/js/t3-core.js:365`、`:493-498`
- 轮到的座位高亮、赢家发光；名牌与头像钉在 3D 投影点上。`apk/assets/www/js/t3-core.js:521-523`、`:541-558`；样式见 `apk/assets/www/css/t3-ui.css:93-116`、`:175-202`
- 说话时冒气泡、头像点头、人物嘴动。`apk/assets/www/js/t3-core.js:526-538`
- 3D 人物按事件做动作/表情：摸牌、出牌、碰杠、胡牌、被砸、输牌垂头丧气；动作有 soft 防打断，表情有时长。`apk/assets/www/js/t3-chars.js:174-235`、`:250-283`
- 结算后赢家/输家/围观者的话与道具反应。`apk/assets/www/js/game.js:253-288`

**机制**：性格不是藏在数值里，而是通过**低成本、可节流**的视觉/文本信号持续暴露；3D 人物是加分项，不是必要条件。

**原创实现要点**
- 首版只做 2D：座位名牌加“性格标签”（4 字内）+ 颜色点；事件时冒一句原创短气泡 + 一个 emoji/CSS 表情；轮次边框高亮。
- 反应节流：同一座位 ≥2.5 s 一次、同一事件类型不连续两次；气泡不遮挡手牌/按钮。
- 尊重 `prefers-reduced-motion`：关闭抖动/发光动画，只保留静态标签与文字。
- 若将来接入 3D 人物，也只做“动作/表情事件接口”，不复制对方模型与骨骼。

**风险**：文本噪声、遮挡操作、移动端溢出。缓解：短句上限、气泡自动消失、360 px 宽度测试。

### B. 音效与报牌体验

#### B1. 三条独立音量总线 + 压缩器

**证据**
- 音效/语音/音乐各一个 Gain，统一进动态压缩器再到输出。`apk/assets/www/js/audio.js:7-18`
- 三路音量来自存档，分别乘 0.6 / 1.25 / 0.42 的基准系数。`apk/assets/www/js/audio.js:28-33`；默认值在 `apk/assets/www/js/core.js:337`
- 设置里三个滑杆（0–100，步进 5），松手保存并试听。`apk/assets/www/js/ui.js:691-701`
- 浏览器要求用户点过屏幕才能出声：首次交互时 `resume`，状态变为 running 后再启动音乐。`apk/assets/www/js/audio.js:10-25`、`:23`

**原创实现要点**
- 单个 `AudioContext`，懒初始化；`master compressor → destination`，下挂 `sfx / voice / music` 三个 Gain。
- 三路音量持久化到现有设置对象；默认值参考：音效 70、报牌 80、音乐 0（本项目首版可不做音乐）。
- 页面隐藏时把总音量降到 0 或挂起；恢复时渐变回来，避免“后台突然响”。
- 所有播放函数对 `AudioContext` 不存在/被拒绝的情况静默降级。

**风险**：自动播放策略、iOS 静音开关、节点泄漏。缓解：只在用户手势后初始化；复用节点；提供全局静音。

#### B2. 音效库：约 50 个命名音效，全部实时合成

**证据**
- 合成原语只有两种：带包络的振荡器、带滤波器/包络的噪声。`apk/assets/www/js/audio.js:36-52`
- 音效表约 50 个，按用途可分组：
  - 界面/通用：按钮、筹码单击/连击、翻牌、甩牌、轮次提示、倒计时滴答/钟声/警报、完成音。`:56-69`
  - 牌桌：麻将牌拍桌、自动麻将机、盖子升降、牌墙升起、洗牌、锣、鼓。`:111-118`
  - 骰子/轮盘：骰子哗啦、轮盘滚珠/落格。`:119-126`
  - 胜负：赢的唢呐/笛子/锣鼓短曲，输的二胡短曲，大赢加强版。`:70-90`
  - 金币/奖励：金币、红包、闪光、烟花、筹码雨。`:107-110`
  - 道具/互动：扔、挥、溅、爆炸、亲吻、拖鞋、板砖、奶油、雪球、锤子、雷劈、鼓掌。`:91-106`
- 每个音效都用“频率/滤波/时长/音量/滑音”的短参数组合；筹码、洗牌、骰子等用随机频率/随机延迟避免机械感。`apk/assets/www/js/audio.js:57-58`、`:116`、`:126`；本项目现有音效也有 ±10% 随机音高（`index.html:3151`）

**原创实现要点**
- 首版做 12–14 类，覆盖本项目真实事件：按钮、选牌、出牌、摸牌、碰、杠、胡、流局、倒计时、错误、轮次、结算赢/输、金币、静音提示。
- 每类 1–3 个变体（音高 ±8%、噪声滤波不同），用参数表驱动；不复制对方的波形配方与旋律。
- 交互音短（≤120 ms）、结算音可到 1.5 s；所有音效走同一 `playSfx(kind, opts)`，内部去重与限流。
- 音量归一化：同类音效峰值接近，避免“碰”比“胡”还响。

**风险**：刺耳、过密、CPU 抖动。缓解：压缩器、限流、快速模式只保留结构音。

#### B3. 事件驱动 + 去重 + 防堆积

**证据**
- 事件演出层每个事件只做一次声音：出牌 `tile`、摸牌 `deal`、吃碰 `slap`、杠 `allin` + 闪电/光环 + 震屏、刮风/下雨、胡 `gong`、结算 `win/bigwin/lose`。`apk/assets/www/js/t3-mj.js:298-363`
- 轮到玩家：`turn` + 30 ms 震动。`apk/assets/www/js/t3-mj.js:236`
- 发牌：16 次 `deal` 以 100 ms 间隔触发；收牌/升墙/洗牌/机器各有独立音效。`apk/assets/www/js/t3-mj.js:288`、`:392-410`
- 掷骰：推近镜头时 `dice`，落定 `ding`。`apk/assets/www/js/t3-mj.js:419-425`
- 事件积压超过 9 个进入快速模式，跳过语音/部分演出。`apk/assets/www/js/t3-view.js:49-67`
- 2 倍速以上不报牌名，避免叠成一片。`apk/assets/www/js/t3-mj.js:306`

**机制**：声音不是“界面重绘的副作用”，而是**对局事件的投影**；快速模式是全局闸门。

**原创实现要点**
- 本项目现有 `sfxCheck` 用状态签名变化触发（`index.html:3158-3178`），可保留思路但升级为显式事件：引擎落子/摸打/结算时发 `sfx('discard', {seat})`，不再靠 diff 猜。
- 去重键：`kind + seat + handNo + turnCount`，同键 200 ms 内只响一次。
- 并发上限：同时最多 3 个短音效；报牌与音效互斥（报牌时 duck 音效）。
- 快速/连续操作：只保留“出牌、碰杠、胡、结算”，跳过摸牌与按钮音。
- 页面隐藏、静音、无 AudioContext 时全部短路。

**风险**：重复触发（重渲染/回放）、事件丢失、快速模式下漏掉关键音。缓解：以引擎事件为准；结算/胡牌设最高优先级，永不被限流吞掉。

#### B4. 报牌与喊牌：只报关键音，且可静默降级

**证据**
- 牌名表：万/条/筒各九张 + 东南西北中发白，共 34 个中文名。`apk/assets/www/js/chars.js:470-473`
- 出牌时报牌名，且只在 1 倍速/低于 2 倍速时报。`apk/assets/www/js/t3-mj.js:306`
- 吃/碰/杠：先冒气泡说“吃/碰/杠”，再用语音喊对应的短词；杠还配闪电、光环、震屏。`apk/assets/www/js/t3-mj.js:311-325`
- 胡/自摸：说“胡/自摸”，再喊“胡啦/自摸”，赢家发光。`apk/assets/www/js/t3-mj.js:335-345`
- 语音播放：按角色映射 5 种音色；每个角色有播放速率微调；随游戏倍速再加速；找不到对应语音就**完全不发声**，不退化为系统朗读。`apk/assets/www/js/audio.js:173-185`、`:228-243`、`:176`
- 同时最多 3 个人说话；解码缓存只留最近 70 条；机器人语音加短回声做出金属腔。`apk/assets/www/js/audio.js:193-226`
- 聊天/喊话：冒泡 + 用该座位嗓音念出来；页面隐藏时不念。`apk/assets/www/js/t3-core.js:534-538`、`:13-14`

**机制**：报牌是“**事件 → 文本 → 声音**”的三段式，声音可有可无；文本永远在，声音是增强。这样没有语音包也不会破坏体验。

**原创实现要点**
- 用浏览器 `speechSynthesis` 做可选报牌（默认关）：`lang='zh-CN'`，`rate` 1.0–1.25（按人设手速微调），`volume` 走独立报牌总线。
- 只报三类：**自己/下家出牌名**、**吃碰杠胡**、**轮到自己**；不逐张报别家摸牌。
- 队列最多 1 条：新事件直接 `cancel()` 旧的；回合切换、结算、页面隐藏时取消。
- 特性检测：`speechSynthesis` 不存在、没有中文嗓音、被策略拒绝 → 完全静默，不抛错、不退回英文。
- 频控：同一座位 1.2 s 内不重复；快速模式/倍速 ≥2 关闭；设置里“报牌：关/仅关键/全部”三档，默认关。
- 若不想依赖系统 TTS，可只做“文字气泡 + 短合成提示音”，同样满足“报牌体验”的最低要求。

**风险**：TTS 音色/质量因设备而异，可能带网络请求；与音效重叠；部分浏览器首次调用需要手势。缓解：默认关、明示“使用系统语音”、只报关键、与音效 duck、用户手势后预热。

#### B5. 音乐：气氛驱动、段落切换、让位

**证据**
- 每个游戏/玩法一首主题，民乐或酒廊编制；大厅另有迎宾曲。`apk/assets/www/js/audio.js:304-369`
- `mood(0..1)` 设定气氛，但只在乐句/小节边界换档；速度用两三小节渐变，避免一惊一乍。`apk/assets/www/js/audio.js:660-721`
- 紧张段落进入快、退出慢（奏完八小节再回）。`apk/assets/www/js/audio.js:704-712`
- 胜负短曲响时把音乐压低（duck），结束后恢复；短曲未播完不重复触发。`apk/assets/www/js/audio.js:136-158`、`:679-684`
- 牌墙越少，气氛值越高。`apk/assets/www/js/t3-mj.js:301`

**机制**：音乐是“气氛层”，不是信息层；所有切换都在结构边界，且有 duck 让位。

**原创实现要点**
- 本项目首版不建议做完整配乐（收益/工作量比低、易烦）。若做，只做一段可循环的五声音阶 pad，两层强度（平静/紧张），在回合边界切换，默认音量很低、可关。
- 胜负提示用短音效而非短曲，避免与报牌抢注意力。
- 任何音乐都必须让位于报牌与关键音效。

**风险**：版权（不能听抄）、重复疲劳、移动端耗电。缓解：原创参数合成、默认关、淡入淡出。

#### B6. 时长表与倍速：所有等待统一缩放

**证据**
- 主循环为每种事件定义基础时长：发牌 3000、定缺 1300、摸牌 340、出牌 520、吃碰 1080、杠 1480、胡 3500/4400（大牌更长）、结算 3700 ms。`apk/assets/www/js/mj.js:969-981`
- 所有等待走 `PK.nap`，内部除以 `PK.View.speed`。`apk/assets/www/js/core.js:345`
- 3D 层同理：`T3.nap` 按速度缩放。`apk/assets/www/js/t3-core.js:590-591`
- 事件积压 >9 时进入 fast，直接同步到最新状态、不演中间过程。`apk/assets/www/js/t3-view.js:53-59`

**原创实现要点**
- 建一张 `DUR = { deal, draw, discard, claim, win, settle }` 表，所有动画/等待从表取值；倍速 1/1.5/2 只除这一个系数。
- 用“代次令牌”（本项目可复用现有 `handNo`/`gen` 思路）取消过期动画；快速模式直接渲染终态。
- 测试用假时钟，避免 `setTimeout` 造成 flaky。

**风险**：动画漂移、快速模式状态不同步。缓解：终态渲染 + 令牌取消 + 单测。

### C. 3D / 桌面演出

#### C2. DOM 信息贴 3D 投影点

**证据**
- 座位牌/气泡/标签不是画在 3D 里，而是 DOM 元素按投影坐标定位，并夹在屏幕安全区内。`apk/assets/www/js/t3-core.js:464-523`、`:541-558`

- 3D 人物模式下，名牌挂在人物头旁边，点名牌也能互动。`apk/assets/www/js/t3-core.js:541-551`

**原创实现要点**
- 本项目 2D 已有座位牌；只需保证“飘分/标签”不超出容器、不遮按钮。
- 若 3D 模块暴露投影接口，可用它定位 DOM；否则不要反向修改 3D 内部，保持解耦。

**风险**：与 3D 内部耦合、重排抖动。缓解：只用公开 API；位置变化做过渡；限制更新频率。

#### C3. 飘分 / 分级横幅：小、中、大三档

**证据**
- 每家输赢在头像上冒带正负号的飘字（字号 2.4 单位），飘字本身约 1.7 s 向上淡出。`apk/assets/www/js/t3-mj.js:226-227`；实现 `apk/assets/www/js/t3-fx3d.js:184`；`apk/assets/www/js/t3-fx.js:89-91`
- 胡牌横幅分三档：小横幅、大横幅（镜头轻推 + 星芒 + 光环）、终极横幅（金光）；横幅由原生画成贴图，立在桌面上空、正对镜头。`apk/assets/www/js/t3-fx.js:275-291`
- 飘字统一是向上飘 1.7 s 的文本粒子。`apk/assets/www/js/t3-fx.js:89-91`
- 胡牌时按倍数决定烟花数量与金币雨规模。`apk/assets/www/js/t3-mj.js:352-355`

**原创实现要点**
- 2D 实现：座位牌旁 `+12` 飘字（CSS keyframes，1.2 s，向上 20 px，淡出）；结算用一张横幅，按番数/鸟数分 3 档颜色与动效；不做全屏粒子。
- 信息层级：飘分 < 横幅 < 结算面板；同一时间只允许一个横幅。
- 数字用等宽/表格数字，避免跳动；正负色对比度达标。

**风险**：遮挡、视觉噪声、低端机掉帧。缓解：单横幅、CSS 动画、可关闭“特效”。

#### C4. 奖励演出与性能闸门

**证据**
- 烟花：升空→球状爆开（彩色长尾、白色短芒、闪烁星芒、扩散光环）。`apk/assets/www/js/t3-fx.js:96-125`
- 金币雨：2D 粒子 + 3D 金币从天上掉到桌面弹两下；最多 40 枚。`apk/assets/www/js/t3-fx.js:126`、`apk/assets/www/js/t3-fx3d.js:411-426`
- 震屏、吊灯闪一下、镜头 punch。`apk/assets/www/js/t3-fx.js:92-94`、`apk/assets/www/js/t3-core.js:928-936`
- 画质档位直接缩放粒子数量（`part` 0.4–1.5）；主菜单闲置 30 s 后停止渲染省电。`apk/assets/www/js/t3-core.js:697-790`、`:815-837`

**原创实现要点**
- 只在“大胡/自摸/高番”触发，且受“特效强度”设置控制；默认轻量。
- 用 CSS 实现金币/彩带（≤20 个元素），`animationend` 移除；不用 canvas 常驻循环。
- `prefers-reduced-motion` 或低电量模式下降级为静态横幅 + 一声提示音。

**风险**：性能/晕动/喧宾夺主。缓解：上限、可关、静态降级。

#### C5. 自动麻将桌叙事（只记录，不列为差距）

**证据**
- 开局流程：上一局的牌推进桌心→中控台升起→机器洗牌→四面牌墙从槽里升起→镜头推近掷骰→按点数开门→四张一轮抓牌。`apk/assets/www/js/t3-mj.js:1-6`、`:268-291`

- 牌墙按骰子点数决定开门位置；摸牌从前端、杠后从后端补。`apk/assets/www/js/t3-mj.js:85-111`

**风险**：重复造轮子、破坏现有 3D 稳定性。

#### C6. 3D 人物实体（不建议）

**证据**
- 每个对手是坐在桌边的 3D 人物，有手部握牌、躲牌、动作、表情、视线、被道具砸中的反应；镜头会为头顶重新取景。`apk/assets/www/js/t3-chars.js:14`、`:174-283`、`:427-445`；`apk/assets/www/js/t3-core.js:54-69`
- 依赖大量角色资产与骨骼/表情系统（`chars-data.js` 3.6 MB、`chars/*.png`、原生渲染）。

**结论**：与“单文件、离线、零构建、测试全绿”冲突，首版不做。用“头像 + 标签 + 气泡 + CSS 表情”替代。

### D. 交互手感

#### D1. 两段点击：先选中抬起，再点同一张打出

**证据**
- 点到自己手牌：第一次选中并抬起，第二次同一张才打出；打到不允许的牌（万能牌/缺门）给提示。`apk/assets/www/js/t3-mj.js:508-524`
- 命中检测：把牌的四个角投影到屏幕，判断点是否在四边形内。`apk/assets/www/js/t3-core.js:356-359`；`apk/assets/www/js/t3-mj.js:508-514`
- 从牌上开始拖动会在牌间扫选，不会转镜头；从空白处拖动才 orbit；双指缩放/平移。`apk/assets/www/js/t3-core.js:635-687`
- 按钮放在自己手牌上方、靠右，避免挡住牌河；没有新按钮时旧按钮播放退场动画。`apk/assets/www/js/t3-mj.js:506`、`apk/assets/www/js/t3-core.js:614-619`、`:579-589`

**本项目对照**：已有触摸两段点击与键盘快捷键（`index.html:3963`、`:4024`、`:4414-4417`），属于已具备能力。建议只做回归测试：选中/取消/切换/打出、禁用牌提示、拖动不误出牌。

**风险**：触摸与鼠标行为不一致、误触。

#### D2. 只显示当前合法动作 + 教练提示

**证据**
- 轮到自己：只显示“自摸/杠/提示”和手牌；吃碰杠胡按合法项逐个生成按钮；“过”是灰色次要按钮。`apk/assets/www/js/t3-mj.js:234-263`
- 提示按钮按“打出后向听数最小、同分先打字牌/幺九”排序，循环给出建议，并把对应牌抬起；提示语明确“再点一下这张牌就打出去”。`apk/assets/www/js/t3-mj.js:244-252`
- 定缺按钮标注“推荐”，但仍由玩家选择。`apk/assets/www/js/t3-mj.js:237-239`
- 按钮有禁用态与按压位移，避免误触。`apk/assets/www/css/t3-ui.css:38-54`

**原创实现要点**
- 保持“只给合法动作”；教练提示与“对手性格”解耦：提示只基于公开信息与牌效，不读取对手暗牌。
- 提示按钮给出“理由一行”（如“打这张，向听不变且有效张最多”），教学价值高于只高亮一张牌。
- 危险动作（如拆听）二次确认？练习模式不建议弹窗打断，用颜色/文案警示即可。

**风险**：提示变成“代打”、降低练习价值。缓解：提示分级（思路/具体牌）、记录使用次数、考试模式关闭。

#### D3. 加速、跳过、防堆积

**证据**
- 事件队列积压 >9 → fast：直接同步最新快照，不演中间过程；语音/人物小动作跳过。`apk/assets/www/js/t3-view.js:49-67`
- 倍速 1/2/3，所有等待按比例缩短；设置里有“正常/快/极快”。`apk/assets/www/js/ui.js:685-686`、`apk/assets/www/js/core.js:345`
- 离开牌桌/重开一局会取消演出并复位。`apk/assets/www/js/t3-mj.js:486-497`

**原创实现要点**
- 本项目已有“快进/自动”类能力可复用；新增演出必须支持“立即到终态”，不能阻塞下一手。
- 用 `handNo + gen` 作废过期回调；页面隐藏时暂停计时与语音。
- 快速模式下报牌、飘分、粒子全部关闭，只留结算。

**风险**：状态不同步、回调泄漏。缓解：终态渲染、令牌取消、清理定时器。

### E. 教练与胜率提示（只记录，不优先）

**证据**
- `winProb` 只用自己手牌与公开牌，按向听、巡目、有效张估算最终胡牌概率；不读取对手暗牌。`apk/assets/www/js/mj.js:920-958`
- 只在单机、且设置开启时计算；开启期间对局不计入战绩。`apk/assets/www/js/game.js:48-62`；`apk/assets/www/js/ui.js:704-714`
- 结果显示在自己名牌上方，按 60%/40% 分三档颜色。`apk/assets/www/js/t3-core.js:803-813`

**结论**：本项目已有更深的“对手采样 + 放铳概率 + 决策报告 + 训练讲解”（`index.html:3186-3205`、`:3446-3447`、`:1525`），不需要借它的估计公式。可借的只有产品原则：**估计必须标注为估计、只在练习生效、使用期间不计入评估**。

### F. 规则变体（只记录，不建议照搬）

**证据**
- 四种玩法共用引擎，差异写在 `RULES`：推倒胡（可吃碰、字牌）、血战到底（无字牌、可定缺、胡了继续打）、鸡平胡（番型计分）、红中麻将（红中万能、不能打出、手里有红中只能自摸、胡后扎鸟）。`apk/assets/www/js/mj.js:11-24`
- 缺门：定缺后必须先打完缺门牌；听牌/胡牌都受限。`apk/assets/www/js/mj.js:284-294`、`:363-371`
- 红中：万能牌参与胡牌判定；手里有红中不能接炮（抢杠除外）；四张红中直接胡。`apk/assets/www/js/mj.js:99-104`、`:243-253`
- 扎鸟：胡后从牌墙翻 4 张，一/五/九/红中算中鸟，每中一只加一倍底分，不受封顶限制。`apk/assets/www/js/mj.js:232-241`、`:165`
- 血战流局：查花猪（还留缺门牌）与没叫（没听牌），按番赔付。`apk/assets/www/js/mj.js:537-574`
- 番型与封顶：各玩法不同，`cap` 限制倍数。`apk/assets/www/js/mj.js:112-167`

**结论**：这些是公共玩法机制，不是本项目“转转麻将”的规则。记录在此仅防止下游误把“红中/缺门/血战”当成通用能力；本项目不应为借鉴而改规则，否则会破坏现有测试与结算口径。

- 不要复制 `TEN/DEAL/PWIN`；它们绑定对方的牌张、规则与机器人强度，换到本项目会误导决策。
- 不要把“运势改未见牌”包装成“真实感”；对本训练器而言这是公平性风险（见第六节）。

## 五、推荐给 planner 的 3–5 项

以下是建议进入需求阶段的最小集合。编号 R1–R5，按优先级排序；每项都给出范围、机制、验收与测试建议，便于 t3 收敛为需求、t4 实现。

### R1（P0）对手性格系统 v1：一套 AI + 一层人设参数

**目标**：在不改变现有 AI 强度基线的前提下，让 3 个对手有可区分、可记忆、可解释的打法倾向。

**范围**
- 只改 `index.html` 内联脚本与 `tests/`；不改 `assets/table3d/table3d.js`，不改规则与结算。
- 新增纯函数：`personaFor(seat, seed)`、`personaParams(persona, difficulty)`、`claimBias(persona, ctx)`、`defenseBias(persona, ctx)`。
- 6–8 个自有原型；默认“标准”人设参数 = 当前行为（保证回归）。

**机制**
- 性格维度 6–7 个（进攻、副露、守备、贪大、情绪、手速、粗心），0..1；原型 + 抖动 + 可选头像底色。
- 注入点：`aiDiscard` 的候选评分（防守权重/噪声）、`aiPengDecision`/叫牌门槛（副露欲/贪大）、`aiThink` 延迟（手速）、结算反应（情绪）。
- 难度只调“算力/失误”，不调“性格”；评估模式可强制标准人设。

**验收**
- 默认设置下，行为与现有基线一致（相同种子、相同牌局结果可复现）。
- 每个座位显示性格标签；不同座位在同一局可观察到不同叫牌/防守倾向。
- 无隐藏信息读取：性格决策只使用公开信息与自己的手牌。
- 全量测试通过；新增单测覆盖：默认中性、确定性、叫牌门槛边界、无暗牌访问。

**测试建议**
- 固定种子跑 50 局，统计每个原型的副露率/放铳率/平均打点，确认落在设定区间；不追求精确数值，只防“全都一样”或“全都乱打”。
- 纯函数单测优先，避免依赖 UI。

**风险与缓解**
- 性格导致强度漂移：默认标准、性格强度可关、评估模式固定。
- 玩家觉得“被针对”：明示性格只影响倾向、不改发牌；不引入运势。

### R2（P0）音效基础设施：≥12 类 + 三路音量 + 事件表

**目标**：把现有 5 个音效扩展为覆盖完整对局节奏的音效系统，同时保持零资产、离线、可静音。

**范围**
- 只改 `index.html` 的音频段（现有 `index.html:3102-3178`）与设置 UI、`tests/`。
- 单个 `AudioContext`、压缩器、`sfx/voice/music` 三路 Gain；音量持久化；页面隐藏静音。
- 12–14 类：按钮、选牌、出牌、摸牌、碰、杠、胡、流局、轮次、倒计时、错误、结算赢/输、金币/奖励、静音提示。

**机制**
- `playSfx(kind, opts)`：查表 → 参数化合成 → 限流/去重 → 走 sfx 总线。
- 事件源：引擎动作处显式调用；不再用状态 diff 猜。
- 快速模式只保留结构音；胡/结算最高优先级。
- “报牌”走独立 voice 总线（R3），与 sfx 互斥/duck。

**验收**
- 至少 12 类可区分音效；每类音量感知接近；总开关与三路滑杆生效并持久化。
- 无 AudioContext 环境（Node/测试/旧浏览器）不抛错、静默。
- 连续快速操作不出现明显叠音/爆音；切后台自动静音。

**测试建议**
- 用可注入时钟测试去重窗口与并发上限；用假 AudioContext 记录调用，不真正发声。
- 音量 clamp 0–100、静音短路、隐藏页短路各一条用例。

**风险与缓解**
- 自动播放策略：首次手势后初始化；失败静默。
- 音色刺耳：压缩器 + 统一峰值 + 试听入口。

### R3（P1）报牌体验：文字优先、TTS 可选、默认关

**目标**：让玩家“听见/看见”关键牌与动作，同时不依赖任何语音资产，且可完全关闭。

**范围**
- 牌名表按本项目规则自建（万/条/筒/字牌），只覆盖本项目用到的牌。
- 事件：自己/下家出牌、碰、杠、胡、自摸、轮到自己；不逐张报别家摸牌。
- `speechSynthesis` 特性检测；无中文嗓音/被拒绝 → 静默；默认关；设置三档“关/仅关键/全部”。

**机制**
- 队列最多 1 条，新事件 `cancel` 旧事件；回合切换/结算/隐藏页取消。
- `rate` 按人设手速 0.95–1.25；`volume` 走 voice 总线；与音效 duck。
- 文字气泡始终显示（不依赖 TTS），TTS 只是增强。

**验收**
- 开启后能听到中文报牌；关闭后完全静默且对局不受影响。
- 无 TTS 的浏览器/Node 测试不报错；快速模式/倍速 ≥2 自动不报。
- 报牌不重叠、不延迟出牌、不泄露对手暗牌。

**测试建议**
- 牌名表完整性（每种牌都有名字、无重复）；关闭态零调用；不可用态零异常；事件切换取消。

**风险与缓解**
- TTS 质量/隐私：默认关、明示“系统语音”、不模仿对方音色。
- 与音效打架：voice 优先，sfx duck。

### R4（P1）性格可见层：徽章、气泡、反应

**目标**：让“性格”在桌面上可感知，而不是只在后台数值里。

**范围**
- 座位名牌加性格标签（4 字内）+ 颜色点；轮次/胡牌高亮；事件时短气泡 + emoji/CSS 表情。
- 原创短句池（每类 4–6 句，≤14 字）；节流：同座位 ≥2.5 s、同事件不连续。
- 尊重 `prefers-reduced-motion`；不遮挡手牌/按钮；移动端 360 px 不溢出。

**机制**
- `say(seat, pool)` → 气泡；可选 TTS（R3）；不阻塞对局。
- 情绪状态（R1 可选）驱动“上头/谨慎/手热”三类反应。
- 结算后赢家/输家各一句；不刷屏。

**验收**
- 每个座位能看到性格标签；不同性格在叫牌/防守/台词上有可观察差异。
- 气泡不遮挡操作、不无限堆叠；关闭“桌面互动”后只剩标签。

**测试建议**
- 文案长度/数量检查；节流纯函数测试；ARIA 标签存在性。

**风险与缓解**
- 文本噪声/文化敏感：短句、可关、避免冒犯与真实人物影射。

### R5（P2）轻量演出：飘分、分级横幅、可选金币/彩带

**目标**：提升结算与关键动作的“爽感”，但不引入 3D/大资源/性能负担。

**范围**
- 座位旁飘分（CSS 1.2 s）；结算横幅 3 档（平胡/自摸/大胡）；可选金币/彩带 ≤20 个元素。
- 只在关键节点触发；受“特效强度”设置控制；`prefers-reduced-motion` 降级为静态。
- 不改 `table3d.js`；3D 模式下用 DOM overlay。

**机制**
- 单横幅互斥；动画结束自动移除；终态渲染，快速模式跳过。
- 数字用表格数字，正负色对比度达标。

**验收**
- 结算信息一眼可读；动画不影响下一手；关闭特效后无残留。
- 低端机/快速模式无掉帧或状态不同步。

**测试建议**
- DOM 节点数量上限；重复触发去重；关闭态零动画。

**风险与缓解**
- 视觉喧宾夺主/晕动：默认轻、可关、静态降级。

### 建议顺序与依赖

1. **R2（音效基础）** 与 **R1（性格）** 可并行，互不依赖。
2. **R3（报牌）** 依赖 R2 的 voice 总线与静音策略。
3. **R4（可见层）** 依赖 R1 的人设数据与标签。
4. **R5（演出）** 独立，最后做；只做 2D/CSS。

### 明确不做

- 不改麻将规则、计分、鸟数、结算口径（避免破坏现有测试与验收）。
- 不引入预制语音/音乐/角色资产；不复制 APK 的任何文案、头像、名称、音色。
- 不复制 `TEN/DEAL/PWIN/PACE` 等统计表；不做“运势改未见牌”。
- 不重写 3D 牌桌；不改 `assets/table3d/table3d.js`。
- 不为“像 APK”而加入红中/缺门/血战等变体。

## 六、未验证与风险

### 6.1 未验证

- **未运行 APK**：所有结论来自静态阅读；音效实际听感、TTS 质量、3D 帧率、动画手感均未实测。
- **原生层未逆向**：原生 3D 渲染库（任务所述 table3d 库）、权限、网络、支付均不在本次范围；只确认网页层是数值帧生产者。
- **版本漂移**：行号对应本次解包的 0.41.0；若 APK 升级，锚点可能偏移。
- **统计表来源**：对方注释称由机器人自对局统计；未独立验证其校准质量，也不建议使用。
- **本项目运行环境**：未在目标手机/浏览器上实测 AudioContext、speechSynthesis、低端机性能；需 t5 验证。
- **法律判断**：本文只做技术分析，不构成法律意见；商标/著作权/声音权益需按实际使用评估。

### 6.2 风险清单

| 风险 | 说明 | 缓解 |
|---|---|---|
| 公平性感知 | 性格/情绪影响决策，玩家可能认为“被安排” | 默认标准、明示只影响倾向、评估模式关闭、绝不改发牌 |
| 难度与人设混淆 | 性格强的弱智感 vs 难度高的强压感 | 两轴分离；难度只调算力/失误；提供“性格强度”档 |
| 训练价值下降 | 性格噪声干扰练习判断 | 练习模式可固定标准人设；复盘标注对手性格 |
| 自动播放限制 | 浏览器/WebView 要求手势后才能出声 | 首次手势初始化；失败静默；提供手动“开启声音” |
| TTS 不可用/质量差 | 设备无中文嗓音、离线、隐私策略 | 默认关；特性检测；文字气泡兜底；不模仿对方音色 |
| 性能/电量 | 粒子、动画、TTS 同时触发 | 上限、CSS 动画、快速模式降级、页面隐藏暂停 |
| 单文件体积 | 不能内嵌音频/模型 | 只程序合成；TTS 用系统能力；不新增资产 |
| 测试不稳定 | 定时器/音频/随机 | 纯函数 + 注入时钟 + 固定种子；浏览器 API 隔离 |
| 版权/商标 | 文案、角色、语音、音乐、代码 | 遵守第四节；只提炼机制，重写实现 |

### 6.3 对“单文件、离线、零构建”的具体影响

- 新增音效与报牌必须**内联在 `index.html`**，不新增 `assets/` 文件；TTS 用系统能力，不下载语音。
- 3D 是既有例外（`assets/table3d/` + vendor + GLB，且 `file://` 下会失败，见 `index.html:2660`）。因此 R1–R4 必须在 2D 模式完整可用，不能依赖 3D。
- 所有新设置默认值要保守：报牌关、音乐关、特效轻；保证“打开就是原来的练习器”。
